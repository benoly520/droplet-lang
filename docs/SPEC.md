# SPEC：一个给 AI 用的可验收 C 工程

> 一句话：**源码是合法 C11，加几张声明表；让 AI 写得出、让检查抓住错、让人只看结果。**
> “超集”在本仓库只有一条含义：**合法的 C 程序不会被这一层拒绝**。不给 C 新增语法，也不再对它做任何语言扩展。
> v0.38 的 `lang/` 是另一码事：一门不碰 C、不进题面、带自杀条款的实验性登记介质，边界写在 §2.2。

## 1. 这是什么

三种角色的分工是固定的：

| 角色 | 做什么 | 不做什么 |
| --- | --- | --- |
| AI | 写实现、写声明、自己跑检查 | 不解释过程，不自证正确 |
| 编译器 / 构建脚本 / 检查器 | 在构建期和验收期让错的实现失败 | 不判断业务对不对 |
| 人 | 看结果（能跑吗、断言全绿吗、改坏会红吗） | 不逐行读实现 |

所以这个东西的产出不是“语法”，是**一条能从声明走到运行实现的、会失败的检查链**。

“给 AI 用”在这里指**作者是 AI**，不是指语言或工具为 AI 做了特殊设计；语法与工具链与普通 C11 无异。
是否真的让 AI 写出更可靠的 C：决定层有一次可重复的小规模测量（3 次独立生成，首次即 12/12，
`EXPERIMENT §1`）；**整套服务仍未测量**，也没有人类维护者参与过实验。

## 2. 为什么留在 C 里，不再造语言

这个仓库**曾经**是一门新语言（自己的词法、语法、类型检查、代码生成，4727 行），v0.33 之后删掉了。
放弃的理由是实测的三条，不是偏好：

1. **出生成本**。新语言的每个新词都要付“造词 × 出现频次 × 锚例数”的教学成本；留在 C 里接近 0 ——
   AI 已经会 C，多出来的只有几张表。
2. **可验证性没有赢**。拿同一个服务用纯 C 写一遍做对照：四条纪律里三条语言占优，但
   “可执行样例 + 机械变异”这条**打平**（C + 样例 + `-Werror` 同样 6/6）。
3. **致命的一条**：语言声明的 invariant 被自己的旗舰服务违反（同一 key 连 POST 两次回 201 / 201），
   而 C 对照组靠一句手写的 `if` 守住了。语言多出来的那层没有把“目标→实现”变成会失败的通路。

结论写在代码里而不是文档里：`.dlt` 前端已删除，验收由 `code/sup/` 承担。

### 2.1 决定：不再做语言扩展

明确不做，不是“暂时没做”：

- 不加新语法、不加编译器分支、不做注解检查器；
- “超集”只承诺一条 —— 合法 C11 在本层下仍然编译、仍按 C 语义运行（`compat-sup.sh` 5/0 在守）；
- 将来若某类缺陷反复发生且**只有编译器看得见**，先做独立检查器，也不改语法。

理由是收益与成本不对称：AI 的失败模式是**静默漂移**，不是不会写 C 语法；语言扩展对这个问题
边际收益低，成本却是永久的（绑工具链版本、每条检查配正反例与破坏测试、所有工具要重新支持）。
一次 4727 行的实证已经付过学费。

### 2.2 v0.38 的 `lang/`：边界要说清，不然这条决定就变成一句空话

上面那条决定仍然成立，且这条没有为它让路：`.dpt`（`lang/droplet.dpt` + `code/sup/dpt-check.py`）
**不改 C 语法、不加编译器分支、不做注解检查器**，C 那套的每条门一个都没动。它造的是另一样东西：
一门**只用来登记“需求 ↔ 判据”关系**的小语言，运行在 Python 检查器里，不进 C 前端。

三点让它不构成对 §2.1 的偷偷违背：

1. 它是**介质替换**而不是**保证替换**。`req/` 五份表格一个都没删，`lang/blobd.dpt` 由
   `--emit req/` 机械生成，`lang-check.sh` 用 `--against` 逐栏证明两者表达同一批承诺（19 / 16 / 4 / 9）。
   也就是说：语言版没多承诺任何东西，也没有把哪条旧保证降级。
2. 它**不在题面冻结里**。`lang/` 被有意排除在 `freeze.sh` 的 `FILES` 之外，所以它不是一道新题，
   `req/FROZEN` 仍是 12 项 —— 换介质不等于换题。
3. 它带着**自杀条款**（见 [LANG2.md](LANG2.md) 第 6 节）：定义超出 1,500 token 预算、或三臂实测
   测不出优势，就退回表格。本轮判定是「留着，但降级为实验性介质」，不是「转正」。

真正新增的概念只有三个 —— 认领（`wire`）、署名（`evidence`）、状态（`status`），其余是把表格里
靠约定成立的东西写成会失败的语法。这件事值不值得，取决于下一轮能不能把 `req/` 真正换掉而不丢门禁。

## 3. 形态

### 3.1 四张表

| 表 | 在哪 | 内容 | 展开成 |
| --- | --- | --- | --- |
| `DP_ROUTES` | `code/sup/blobd.c`（用户） | 路由 × 实现 × 成功投影 × 鉴权 × 守卫 × 理由 | handler 原型 + 分发器 + 守卫调用 |
| `DP_ENVS` | `code/sup/dp_env.h`（用户） | 环境变量 × 字段 × 类型 × 默认值 | 配置结构 + 唯一的读取函数 |
| `DP_GOALS` | `code/sup/blobd.c`（用户） | 每条服务目标由哪几条断言证明 | 契约的 `goals` 节（`--contract` 导出） |
| `DP_EXAMPLES` | `code/sup/dp_decide.h`（用户） | 纯决定的封闭样例（19 条） | 可执行 oracle |

没有新语句、没有新表达式、没有宏魔法去改 C 的既有含义 —— 一份普通 C11 程序 include 这一层，
`cc -std=c11 -Wall -Wextra -Werror` 照常编过（`compat-sup.sh` 在守这条）。

### 3.2 归属

- **用户所有**（AI 写的部分）：`blobd.c` 232 行、`dp_env.h` 18 行、`dp_decide.h` 77 行、`dp_decide.c` 37 行。
- **机制**（不该由 AI 每次重写）：`dp_sup.h` 161 行、`dp_cfg.c` 56 行、`dp_conf.h` 35 行、`dp_oracle.c` 92 行。
- **运行时**（服务真正干活的 C）：`code/runtime/` 1474 行（含 `rt.h`）—— `rt_core` / `rt_http` / `rt_blob` / `rt_ver`。
- **验收与检查**：`code/sup/*.sh`、`code/webapi/deploy/accept-table.sh`。

### 3.3 旗舰服务

`blobd`：一个小型 blob 存储。POST 建 key、PUT 写版本（带 `If-Match` 预条件）、GET 读、
DELETE 不实现（405）、每次成功写入留快照与一条 git 提交。30 条 wire 断言把它的对外承诺钉住，
其中 #25/#26 专门钉鉴权（错 token / 没带 token -> 401，且判断与服务链接的是同一份），
#27 钉清单的外壳与顺序（`{"keys":[…]}` 字典序，来自 v0.36 的一句新文本需求 `S14`），
#29 钉空清单也是合法对象（还是 `S14` 那句，v0.37 补的判据）、#28 钉带表示的成功响应声明
`application/json`（`S15`，散文从没写过，是 v0.37 的 A/B 实验里“没人敢改”的那一条把它逼成了一句需求）。

## 4. 检查面（核心）

| 检查 | 位置 | 失败的样子 |
| --- | --- | --- |
| 表与实现双向对账 | 编译器 | 表里列了不存在的实现 → `used but never defined`；实现没被表引用 → `-Wunused-function` + `-Werror` |
| 符号审计 | `audit-sup.sh` | 用户 TU 的 `.o` 出现 `getenv` / `environ` / `socket` / `open` … → 构建红 |
| 接线检查 | `build.sh` | 被样例覆盖的决定没有被服务引用（`nm -u` 查不到）→ 构建红：“样例验的不是跑的那份代码” |
| 样例 oracle | `oracle-sup.sh` | 逐条跑 `DP_EXAMPLES`（19 条），一条一个进程；零条可执行样例算失败，崩溃单列 |
| 机械变异 | `mutate-dec.sh` | 13 个变异体逐条断言结局：10 抓住 / 2 MISS（等价变异人工标注）/ 1 编译期响 |
| wire 断言 | `accept-table.sh` | 30 条，每条带期望值，退出码即结论（#30 不问 HTTP，问“敢不敢带病开机”） |
| 契约对账 | `contract-sup.py` | `--contract` 的四节必须齐全；目标里的断言编号不存在 → 退出 1；写 `""` 是显式承认未证 |
| 必读面预算 | `surface-budget.sh` | 写服务必须读的表、类型与参考实现超过 9,000 token / 32 KB → 红 |
| 候选比较 | `compare-sup.sh` | N 份候选里 0 份或 >1 份通过样例 → 红（无解 / 歧义） |
| 首次成功率量尺 | `firstpass.sh` | 给定 attempt 序列，算 first-pass 与 pass@k；**没有模型输入时不产生数字** |
| 维护成本 | `maint-cost.sh` | 三种脚本化改动的文件数或 +/- 行数超过预算 → 红 |
| 检查的检查 | `sabotage-sup.sh` | 23 条破坏，每条必须由一个具体工具以具体诊断抓住，否则整轮失败（#15–#20 是题面/译稿/基线的破坏：删断言行、删译法记录、把歧义改成未定、让“新增”条款在基线上也绿、把“不闭”的缺口改成“未闭”又没人管、反例认领一条不存在的变异；#21–#23 是登记语言的破坏：定义里多写一条不会发生的错误码、完整定义膨胀过预算、写了反例又不署判据） |

### 4.1 一条原则：沉默不算决定

写路由必须表态预条件 —— `with precondition` 或 `without precondition: "理由"`，不写就是编译错误。
写目标必须在 `DP_GOALS` 里写“由哪几条断言证明”，写 `""` 是显式的“未证”。
这两条不是语法糖：它们把“漏写”和“决定不写”从同一个状态里分开。

## 5. 边界与已知口子

不许把这一层说成“安全 C”。它是**检查面**，不是沙箱：

1. **E7**：审计活在 `build.sh` 里。绕开它自己 `cc` 就绕开检查。缓解只有一条：仓库只发布这一条构建路径，CI 用它。
2. **E8**：`dlopen` + `dlsym("getenv")` 在运行时解析，`nm -u` 看不见。
3. **E2（部分）**：实现改成非 `static` 或拆第二个 TU 会削弱 `-Wunused-function` 那一半对账；
   拆出来的 TU 仍会被审计，所以只掉一半。
4. **oracle 只覆盖纯决定**：函数体里只有条件与常量的才算。条件请求、鉴权、body 上限的判断
   都已搬到用户面（`dec_precondition_result` / `dec_auth_ok` / `dec_body_too_large`），
   但**读旧版本、读 header、算 ETag** 仍在运行时 —— 那部分是 wire 断言的账。
5. **运行时不在检查面里**：1468 行 C 是既有资产，改它不受这一层保护。
6. **候选比较只回答样例范围内的问题**：两份实现在样例之外若不同，工具无法替人选；它报“歧义”，
   把猜变成一次失败的运行，而不是给出正确答案。
7. **首次成功率没有测量**：仓库里没有模型在环。`firstpass.sh` 只是量尺，CI 跑的是它的自检。

## 6. 怎么算“这东西有用”

判据只有一条，可证伪：

> 把某个声明（预条件、目标、决定）对应的实现**改坏**，必须至少有一个工具失败；
> 而且不许靠人读代码发现。

`sabotage-sup.sh` 的 14 条就是这个判据的实例化。它自己也会说谎（v0.31 抓到过一次假绿：注入代码少
`#include` 导致编译失败，却被当成“审计抓住了”），所以每条破坏都断言归因，诊断不出现就整轮红。

## 7. 面向“AI 生成、人类维护”的六件事（v0.34）

目标不是新语法，而是让 C 在这个分工里**可写、可判、可维护**。本轮把六件事都落成了 CI 里的命令；
每一件都带自己的失败方式，不靠形容词。

| # | 要解决的问题 | 落点 | 数字 / 结论 | 失败的样子 |
| --- | --- | --- | --- | --- |
| 1 | AI 写服务前要读多少 | `surface-budget.sh` | 29,871 B ≈ 8,270 token（估算），占 200k 上下文 4.1%；预算 9,000 token / 32 KB | 面膨胀 -> 红 |
| 2 | 样例能不能挑出唯一正确实现 | `compare-sup.sh` | 自检 4/4：单份=唯一；等价改写=歧义；两个错版=唯一；只有错版=无解 | 0 份或 >1 份通过 -> 红 |
| 3 | “第一次就写对”有没有数 | `firstpass.sh` + `lab/` | 量尺自检 3/3；决定层实验 **n=3，pass@1=3/3**（首次 12/12）；整套服务未测 | 前 k 次都不过 -> 红 |
| 4 | 契约是不是机器可读 | `blobd --contract` + `contract-sup.py` | 5 路由 / 5 配置 / 18 目标 / 19 样例，四节齐全，未证 0、孤儿断言 0 | 节缺失或编号不存在 -> 红 |
| 5 | 改一处要动多大面 | `maint-cost.sh` | 改默认端口 2 文件/4 个 +/- 行；加配置项 1/3；改边界策略 3/6 | 超预算 -> 红 |
| 6 | 关键判断是不是也在样例里 | 三个决定 + 5 对接线 | 样例 11 -> 19，断言 24 -> 26，接线 3 -> 5，破坏 12 -> 14 | 服务不引用决定 -> 构建红 |
| 7 | 文本需求到题面这一步有没有留痕（v0.36） | `req/SRC.md` + `req/TRANS.tsv` + `req/AMBIG.tsv` + `--baseline` | 14 源句 -> 17 条款（回归 16 / 新增 1）、17 份译法记录、2 条歧义全已定、0 缺口；`#27` 在旧实现上先红后绿 | 条款没译法 / 反例空 / 歧义未定 / 新增在基线上就绿 -> 红 |
| 8 | 反例到底有没有人管、基线会不会自证（v0.37） | `req/BASELINE` + `baseline-sup.sh` + `TRANS` 证据列 + `mutation-score` 的 E 相与台账对账 + `GAP` 三态 | 16 源句 -> 19 条款（回归 18 / 新增 1）、19 份六列译法记录（23 个 `S<n>` + 9 个 `E<n>` 认领，实测全对）、4 条歧义全已定、9 条缺口（不闭 7 / 已闭 2）；L 30/30、E 19/19、S 25/25、覆盖 30/30（floor = 断言总数） | 基线钉成当前 HEAD（自证）/ 认领的编号不存在或实测弄不红本条款 / 缺口写“未闭” / 新增在基线上全绿 -> 红 |

第 6 条的边界值得写死：搬出来的只有**判断**（拿到事实之后怎么判），读写仍留在运行时。
所以它增加了样例覆盖，**没有**把运行时整体纳入检查面（§5 第 4/5 条仍然成立）。

第 3 条的数字口径：pass@k 必须有候选输入才有意义。`EXPERIMENT §1` 用小规模实验给了第一个数，
它只覆盖决定层（n=3、同族模型、题面由人写）；**不要外推成“AI 能写这个服务”**。
完整服务的题面与测量仍然没有，所以 README 的限定词还不能去掉。

## 8. 三条回路（这套东西到底怎么被用）

模型不是靠“读一遍文档”成立的，是靠三条**固定回路**：每条都有输入、命令、失败样子。
缺一条，分工就退回“人读代码”。

| 回路 | 谁跑 | 输入 | 命令 | 失败的样子 |
| --- | --- | --- | --- | --- |
| 作者 | AI | 题面包（声明面，不含实现） | `brief.sh` -> `check.sh` -> `submit-sup.sh` | 首错诊断（哪一项、哪条样例/断言）；提交口拒绝 |
| 维护 | 人 / AI | 现有仓库 + 一句需求 | `check.sh --full` | 一条命令一个退出码，红在第几项 |
| 验收 | 人 | 这一版二进制 | `report.sh --accept` | 某个目标变红；未证目标 > 0 |

### 8.1 题面包（`brief.sh`）

包 = 四张表与类型 + `contract.json` + `TASK.md`。两条断言让包本身可失败：
包里出现实现文件就红；包超过预算就红（v0.36 起 12,000 token：surface 5 + contract + TASK 之外
再装 `req/` 五份译稿，实测 9,886 token，估算）。**包里没有 `dp_decide.c`** —— 那是答案。

### 8.2 作者回路（`check.sh`）

默认七项（构建 / 样例 / 契约 / 需求登记 / 题面冻结 / 预算 / 登记语言，约 5 秒），
`--full` 追加验收 / 变异 / 破坏 / 变异覆盖分（约 7 分钟）。
红就停，只打印**第一个**失败项：后面的红多半是前面造成的，一起报等于没说。

### 8.3 提交口（`submit-sup.sh`）

候选在一份临时树里跑整条面（构建 / 题面冻结 / 19 样例 / 27 断言 / 契约），不碰工作区。
样例全过但接线断开、wire 翻面、或题面被改过的候选，在这里被拒 —— 这是 oracle 单独做不到的。
题面一项排在最前：题被改了，后面全绿也不作数。

### 8.4 人类验收页（`report.sh`）

按**需求条款**（`req/REQ.tsv`）组织，不按断言编号组织：每条条款列出它的**源句、类型、
断言/样例编号**和这一版的红绿，同时显示译稿对账份数、歧义与缺口状态、未证目标、
题面冻结与登记链状态。
没跑验收就写“未跑”，不拿上次的绿冒充这一次。

### 8.5 这一节的边界

三条回路目前只覆盖**决定层 + 对外承诺**。一个 AI 从零写整套服务（路由表、handler、
运行时接线）仍需要读参考实现与 SPEC，这块没有“题面包”形态，也没有测量。
所以“AI 能独立写这个服务”**不在**本轮的证据里；本轮能说的是：决定层可以从声明生成并通过提交口，
维护改动可以在一条命令下收敛，验收可以只看一页。三个实验的数字与限制见
[EXPERIMENT.md](EXPERIMENT.md)：作者 n=3、pass@1=3/3；陌生维护者 1 次、5 文件 / 18 个 +/- 行、全绿。

## 9. 不读实现时，把“正确”做成五道门（v0.35 → v0.36）

问题不是“AI 会不会写对”，而是：需求文档交给 AI，AI 实现，人只验结果、不读代码，
凭什么拦住错的实现？答案不是“保证 100% 正确”（做不到），而是把“对的”拆成五条
**可失败**的链子。任何一条被绕开，另外四条都能被利用。

v0.36 在最前面加了第 0 道门：**翻译**。散文需求不能直接当题 —— 它一词多解，而且从不说自己错。

| 门 | 落点 | 它拦什么 | 失败的样子 |
| --- | --- | --- | --- |
| 翻译层 | `req/SRC.md` + `req/REQ.tsv` + `req/TRANS.tsv`（六列，第六列是证据）+ `req/AMBIG.tsv` + `req/GAP.tsv` + `req/BASELINE` | 把现状抄成需求、把说不定的地方默默选一种、把表达不了的承诺硬写成断言、**写了反例却没人管** | 条款没有译法记录 / 反例栏空 / 歧义未定 / 缺口“未闭” / 反例认领的 `S<n>` 不存在或没红本条款的断言、`E<n>` 没被本条款声明或样例不活 / 基线上“新增”全绿 -> 红 |
| 需求登记 | `req/REQ.tsv` + `req-check.py` | 条款只有文字、断言/样例悬空、目标没人认领、条款与目标声明的证明不一致、**源句没人认领** | 孤儿源句/断言/样例/目标或空证据 -> 红 |
| 题面冻结 | `freeze.sh` + `req/FROZEN` | 把验收表、声明头、**译稿**或契约改简单后再交 | 哈希不符 -> 提交口“题被改过”拒绝 |
| 变异覆盖分 | `mutation-score.py` | 断言是摆设：改期望不红、实现坏了也不红；样例也是摆设 | L 不是恰好红它自己 / E（样例期望取反）不挂它自己 / S 归因不符 / 覆盖低于 floor（floor = 断言总数）/ 台账对账不符 -> 红 |
| 人的一页 | `report.sh` | 人需要读代码才能判断 | 某条条款红、未证目标 > 0、冻结或登记链红 |

五道门的分工不要混：翻译层管“需求到题的这一步有没有留痕”，登记管“条款与证据的链子”，
冻结管“题不能动”，变异分管“断言能分辨好坏”，报告管“人看到的是结果”。
它们仍然都不判断需求本身是否正确 —— 翻译层只是把这件事从“没人看得见”变成“有名字、可对质”。

**先红后绿**是翻译层里唯一直接对实现下判断的一条，v0.37 起**不用人再手动跑**：
基线 commit 记在 `req/BASELINE` 里（`freeze.sh --update` 换题时自动钉住此刻的 HEAD），
`req-check.py` 看见有 `新增` 条款就调 `baseline-sup.sh`：`git archive <基线>` 导出**旧实现**，
只覆盖上当前题面（验收表、声明头、译稿 —— 绝不覆盖 `blobd.c`/`dp_decide.c`/`rt_*.c`，
否则就成了新实现自证），构建出旧二进制再跑一遍这张表。要求每条 `回归` 条款在基线上全绿
（否则登记抄错了或题变了），每条 `新增` 条款至少有一条断言在基线上是红的
（否则这条“新增”其实是把现状复述了一遍）。快速回路用 `--no-baseline` 跳过（不启服务），
`check.sh --full` 与 CI 仍跑全量；浅 clone 导不出基线时 CI 以 `fetch-depth: 0` 兜。

边界写死：这套东西能保证**已知的错法会被指名抓住**、**改题不会静默通过**、
**每次翻译都留下可对质的痕迹**；它不能保证“实现完全正确”，不能保证需求没有漏写，
也不能保证翻译本身不会翻错。把“100%”换成“每条已知承诺都有一条会红的检查
+ 题面不可静默修改 + 翻译有账可查”，才是这句话能兑现的部分。
