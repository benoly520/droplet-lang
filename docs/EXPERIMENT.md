# EXPERIMENT：把"面向 AI 生成、人类维护"变成可重复的数字

> 上一轮把这句话变成了可证伪的命题（量尺、唯一性判据、必读面预算），但一个数都没有。
> 这份文档记三个实验：**冷启动写决定层**、**陌生维护者改一条对外承诺**、**译稿层 A/B**。
> §1/§2 能在干净 clone 上重跑；§3 的树与脚本活在实验机的临时目录里，随沙箱销毁，
> 能重跑的是它留下的账（`S15`/`S16`/`#28`/`#30`/`A3`/`A4`/`G8`/`G9`），不是那 12 次生成。结果与限制一起写。

## 0. 结论先行

| 实验 | 样本 | 结果 | 这个数说明什么 |
| --- | --- | --- | --- |
| 从声明写实现 | 3 次独立生成 | **pass@1 = 3/3**，首次生成即 12/12 样例全过 | 决定层这一小类任务，声明足够写对；三份文件两两不同 |
| 陌生维护者 | 1 次 | **5 文件 / 18 个 +/- 行**，`check --full` 10 项全绿，断言 26 条未删未放宽 | 跨层改动（运行时 + 表 + 断言 + 文档）能在一条命令下收敛 |
| 译稿层 A/B（两轮，12 份实现） | 3+3 / 3+3 | **两臂都是 12/12 通过，0 次分岔**；差别只在“引用了哪里”与“没把握清单里有没有 Content-Type” | 本轮**没测出**译稿层让实现更正确；但盲测臂的猜测清单精确指出了译稿层没登记的账（§3.5） |

三个实验都不覆盖"AI 从零写整套服务"，也都没有人类维护者参与。见 §5。

## 1. 作者实验：从声明写实现（n=3）

### 1.1 题面

`code/sup/lab/` 里放两条**仓库中不存在实现**的纯决定（`dec_retry_delay`、`dec_fresh`）与 12 条封闭样例。

```sh
sh code/sup/lab/make-packet.sh /tmp/lab/packet
```

题面包只有三样：`dp_decide.h`（声明 + 样例）、`dp_oracle.c`（执行器）、`TASK.md`（约束与命令）。
**没有 `dp_decide.c`** —— 那是答案；`make-packet.sh` 会断言包里没有实现文件。

为什么题目要另造：主仓库的 `dp_decide.c` 就在磁盘上，用它测"从声明生成"等于开卷。
这两个函数名在 `code/` 与 `docs/` 里只出现在题面包中（`grep` 可验），所以被测者读不到答案。

### 1.2 隔离与判据

三次生成各在一个空目录里进行，只给该目录的题面包；显式禁止读取仓库与其它尝试目录。
每次交付一个 `answer.c`，判据是题面里的三条命令（`cc` → 链接 → `./oracle`），
12 条样例一条一个进程。

汇总用同一个量尺：

```sh
sh code/sup/firstpass.sh --packet /tmp/lab/packet <含 attempt-01..03.c 的目录> 5
```

### 1.3 结果

```
第 1 次 attempt-01.c：过 12/12
第 2 次 attempt-02.c：过 12/12
第 3 次 attempt-03.c：过 12/12
first-pass: 第 1 次；pass@1=1 pass@5=1
```

- **pass@1 = 3/3**：三次都是首次提交即全过，没有"第 2 次才改对"。
- 三份 `answer.c` 两两不同，但形状只有两种：一份用三目链一次返回，两份用早返回链；
  后两份之间只差一处换行。**声明约束的是行为，不是形状。**

### 1.4 一个反直觉的观察

`compare-sup.sh` 会把"两份都通过"判成**歧义**。在这个实验里，三份都通过并不是缺陷：
独立作者本来就会写出不同的正确实现。歧义判定的适用范围因此要说清楚 ——
它回答的是"**多份候选里挑一份指定的实现**时，样例够不够分开"，不是"正确实现是否唯一"。
把两者混为一谈，就会把"实现自由"错判成"规格不清"。

## 2. 维护实验：陌生维护者改一条对外承诺（n=1）

### 2.1 需求与环境

给一份完整仓库副本（去掉 `.git` 与 `.build`，避免历史与构建产物泄题）与一句需求：

> 服务对"未声明的 HTTP 动词"目前返回 405。改成 501。实现、验收表里相关断言的期望值、
> `DP_GOALS` 的目标措辞要一起维护；不允许删除或放宽断言来变绿。

维护者不知道改动会落在哪些文件，也没有本轮的对话上下文。

### 2.2 结果

| 项 | 实测 |
| --- | --- |
| 改动文件 | 5 个（`rt_http.c`、`blobd.c`、`accept-table.sh`、`SPEC.md`、`VALIDATION.md`） |
| 改动行 | 9 加 / 9 删（18 个 +/- 行） |
| 断言 | 仍是 26 条；#16/#17/#18 期望改为 501，空 body 与无 ETag 两条硬证据原样保留 |
| 全量检查 | `check.sh --full` → **10 项全绿**（含 26 断言、13 变异、14 破坏） |

### 2.3 这次改动暴露的结构

405 的产生点在**运行时**（`rt_http.c` 的 tag → 状态码映射），不在决定层。
所以样例碰不到它，唯一证据是 wire 断言 #16–#18；目标文本也必须同步，否则契约与实现漂移。
这正是 SPEC §5 第 4/5 条说的边界：**判断搬出来了，映射还在运行时**。
18 个 +/- 行也比 `maint-cost.sh` 里"改默认端口 2 文件 / 4 行"大一个量级 ——
维护成本取决于改动落在哪一层，不是常数。

## 3. 译稿层 A/B：给它散文，还是给它译稿（两轮，n=12）

### 3.1 要测的命题

v0.36 把散文译成 `req/`（S → R → 目标 → 断言/样例）。 claim 是：**读译稿的实现者比读散文的实现者更少猜**。
上一轮的端到端验证只证明“这条链子不会漏账”，没证明“它对写代码的人有用”。
这一节就是去测它 —— 而且要先说清楚：**两轮都没测出正差异**（§3.3），
但实验指出了译稿层自己的几处漏账（§3.5），这比一个好看的数字值钱。

### 3.2 设计

同一个 commit（`89a310f`）复制 12 份独立树，唯一变量是树里有没有 `req/`：

| 轮 | 散文 | P 臂 | T 臂 |
| --- | --- | --- | --- |
| 一（P1–P3 / T1–T3） | 整理过的两句话 | 无 `req/` | 有 `req/` |
| 二（M-P1..3 / M-T1..3） | **产品原话，未经整理**：“清单接口返回的是一个光秃秃的数组，前端不好加字段。改成返回一个对象吧，key 列表放在 keys 里面，顺序按字母排一下就行。空的也要能解析，别给人家抛异常。” | 无 `req/` | 有 `req/` |

两臂的任务、约束、交付格式一样，差别只有包。**第二轮两臂的 TASK.md 逐字节相同**（`diff` 验过）；
第一轮不相同 —— T 臂多了一句“先读译稿，按译稿实现”，而 P 臂没有对应的中性句子。
这一句偏向 T 臂，所以第一轮只当旁证，结论看第二轮。
约束三条：只改 `code/runtime/rt_blob.c`；不许读也不许运行 `code/webapi/deploy/accept-table.sh`；
构建必须绿，但不许起服务、不许 curl。交付要**逐字**写两种 body（三个 key / 空目录），
并列出自己没把握的写法。

判据由维护者跑：`accept-sup.sh` 打在每棵树自己的二进制上（P 臂跑不出“期望值泄题”的路径）。
第二轮额外用离线探针复核 corner case（空目录、逆序目录、Content-Type）。

### 3.3 结果：12 份实现，0 次分岔

| 指标 | 第一轮 | 第二轮 |
| --- | --- | --- |
| 验收表 | P 3/3 全过（27/27）、T 3/3 全过 | P 3/3 全过、T 3/3 全过 |
| 交付的两个 body | 6 份逐字相同：`{"keys":["demo","second","third"]}` / `{"keys":[]}` | 6 份逐字相同，同上 |
| 改动面 | 都只动 `rt_blob.c`（`md5` 核对：六棵树的 `blobd.c` 与 `accept-table.sh` 完全一致，`rt_blob.c` 六份互不相同） | 同 |
| 自报“没把握”条数 | — | P 三份共 14 条（均 4.67）；T 三份共 14 条（均 4.67） |

**结论：这一轮测不出译稿层让实现更正确。** 两臂都对，因为这两句话本身没有真分岔：
外壳、键名、排序、空目录四种读法收敛到同一个实现。
“没把握”的条数也没降（两臂同为 4.67 条，一条没少）——所以连“少纠结”这个软指标都没测到。

诚实的边界条件：n=3 每臂；同族模型；第二轮有 2 份自报越界（`M-P3`、`M-T2` 开工时全仓 grep
顺带打印了 `accept-table.sh` 的几行，只到变量赋值与用况标题，没看到期望值）。这不改变结论，
但“两臂都不算严格盲测”这句话必须写在结果旁边。

### 3.4 真正测出来的东西：猜的内容不一样

把两份“没把握”清单逐条对齐，方向相反的一处值得记下来：

| 纠结什么 | P 臂（只有散文） | T 臂（有译稿包） | 为什么 |
| --- | --- | --- | --- |
| “按字母排”是字节序还是本地化排序 | **3/3 都列了** | 1/3 列了 | `req/AMBIG.tsv` A2 已定：key 字符集是 ASCII，按字节序 |
| 数据目录读不到时算不算“空的” | 3/3 列了 | 3/3 也列了 | 包里当时**也没定** —— 这不是臂间差异，是译稿层自己的漏账（后来落成 `S16`/`R19`/`#30`，见 §3.5） |
| 成功响应的 Content-Type 归谁保证 | **0/3 提到** | **2/3 主动提出** | T 臂读了 `REQ.tsv`/`DP_GOALS`，发现这条 wire 承诺没人认领；P 臂压根没往这儿想 |

第三行是这一节最有用的观察：**译稿没有降低不确定性，它把不确定性挪到了该挪的地方**。
读散文的人猜“排序怎么排”；读译稿的人猜“这张表漏了哪条承诺”——
而后者恰好是维护者需要补的账，前者只是实现者的焦虑。

### 3.5 于是实验直接产出了这五处登记（v0.37）

盲测清单里“两臂都纠结”的和“只有读表人发现”的，全部落成了仓库里的东西：

| 来源 | 落到哪 | 机制 |
| --- | --- | --- |
| Content-Type（只有 T 臂提出，散文从没写过） | `S15`（挂“【补，散文未写】”）→ `R18` 回归 → 目标 `content_type_json` → 断言 **#28** | 新断言，实测由变异 **S24** 弄红 |
| “目录读不到算不算空的”（两臂都纠结） | `AMBIG A4` 已定 + `S16`（挂“【补，散文未写】”）→ `R19` 回归 → 目标 `boot_requires_usable_root` → 断言 **#30** | 台账初稿把这一条写成“不可读 -> 500”，**跑了一遍才知道实现是 fail fast**：`stat` 失败或不是目录就退出码 1，压根不带病起进程。台账按实现改，`GAP G9` 随之 **已闭**（#30 是唯一一条不问 HTTP 的断言） |
| JSON 空白风格（R17 的“排除”列原本谎称不约束，而 #27 是精确 body） | `AMBIG A3` 已定：钉紧凑形，判据就是精确 body | 排除列改成实话 |
| 空清单以前根本没判据（#2 只看状态码） | `GAP G8` → **已闭**，用 #29 闭合 | 反例台账点名 G8 |
| 其余 7 条“写了反例却没判据”的边界 | `GAP G1–G7`，状态 **不闭** | 每条必须被自己条款的反例点名 |

顺带修正了一处台账自己打自己的谎：R17 的“排除”列写着“不约束 JSON 空白”，
而 #27 用的是精确 body —— 空白其实被约束了。
这种“排除列与断言集互相矛盾”的谎，机器当场查不出来（要读语义），
但**实现者的纠结清单会把它顶出来**：六个里有五个在为空白猜。这是 A/B 实验的价值所在。

### 3.6 下一轮要测出正差异，题必须这样出

1. 两种读法都要能编译过、能过当时的全部断言 —— 否则判据自己就把答案说了；
2. 其中一种读法违反原意，且译稿把这一条定死了（`TRANS` 译法 + 一条红着的断言）；
3. 本仓库的难点：`dp_decide.h` 的样例表就在实现者手边，它本身已经把许多语义写死了。
   要造真分岔，得像 §1 那样另出一个不带样例表的题面包，而不是给主仓库加需求。

```sh
# 复现第二轮（两臂）
sh /tmp/ab/prep.sh            # 从 89a310f 造 P*/T*，再复制成 M-P*/M-T*
sh code/sup/accept-sup.sh /tmp/ab/M-T1/.build/m-t1/blobd 19164 judge
```

## 4. 复现

```sh
# 作者实验：出题 -> 交给任意模型写 answer.c -> 收成 attempt-01..N.c -> 量
sh code/sup/lab/make-packet.sh /tmp/lab/packet
sh code/sup/firstpass.sh --packet /tmp/lab/packet /tmp/lab/attempts 5

# 维护实验：复制仓库（去掉历史与构建产物），给需求，改完跑
sh code/sup/check.sh --full
```

## 5. 这些数字不能证明什么

1. **任务是决定层，不是完整服务**。路由表、handler、运行时接线怎么从声明生成，本轮没有题面，也没有测量。
2. **样本极小**：作者 n=3，维护 n=1；没有置信区间，不能外推到"AI 一般能写对多少"。
3. **同族模型**。三次生成与维护者来自同一部署配置，不是多模型对比；换模型结果会变。
4. **没有人类维护者**。§2 的"陌生"指没有本轮对话上下文，不是"人类工程师"。
5. **pass@1 的口径是"首次提交即全过"**，不含"跑一次检查后再改"的轮次；真实回路允许迭代。
6. **题面是我写的**。样例覆盖到哪里，实验就只测到哪里；样例之外的行为仍然是猜（§1.4 的歧义边界）。
7. **§3 不可重跑**。那 12 棵树与 `prep.sh`/`probe.sh` 建在实验机的 `/tmp` 下，没有随仓库发布，
   沙箱销毁就没了；能重跑的只有它们的产物（两条新断言、两条歧义定论、两条缺口登记）。
   所以 §3.3 的“0 次分岔”是一次性观察，不是可复现测量 —— 它值钱的地方在 §3.5，不在那个 0。
8. **§3 的 P 臂不是严格盲测**。两份越界自报（`M-P3`/`M-T2`）开工时全仓 grep 打印过验收表的几行；
   第一轮 T 臂还多了一句“先读译稿”。这两处都写在结果旁边，不藏在限制里。
