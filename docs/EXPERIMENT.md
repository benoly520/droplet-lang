# EXPERIMENT：把"面向 AI 生成、人类维护"变成可重复的数字

> 上一轮把这句话变成了可证伪的命题（量尺、唯一性判据、必读面预算），但一个数都没有。
> 这份文档记两个最小实验：**冷启动写决定层** 和 **陌生维护者改一条对外承诺**。
> 两个实验都能在干净 clone 上重跑；结果与限制一起写。

## 0. 结论先行

| 实验 | 样本 | 结果 | 这个数说明什么 |
| --- | --- | --- | --- |
| 从声明写实现 | 3 次独立生成 | **pass@1 = 3/3**，首次生成即 12/12 样例全过 | 决定层这一小类任务，声明足够写对；三份文件两两不同 |
| 陌生维护者 | 1 次 | **5 文件 / 18 个 +/- 行**，`check --full` 10 项全绿，断言 26 条未删未放宽 | 跨层改动（运行时 + 表 + 断言 + 文档）能在一条命令下收敛 |

两个实验都不覆盖"AI 从零写整套服务"，也都没有人类维护者参与。见 §4。

## 1. 作者实验：从声明写实现（n=3）

### 1.1 题面

`code/sup/lab/` 里放两条**仓库中不存在实现**的纯决定（`dec_retry_delay`、`dec_fresh`）与 12 条封闭样例。

```sh
sh code/sup/lab/make-packet.sh /tmp/lab/packet
```

题面包只有三样：`dp_decide.h`（声明 + 样例）、`dp_oracle.c`（执行器）、`TASK.md`（约束与命令）。
**没有 `dp_decide.c`** —— 那是答案；`make-packet.sh` 会断言包里没有实现文件。

为什么题目要另造：主仓库的 `dp_decide.c` 就在磁盘上，用它测"从声明生成"等于开卷。
这两个函数名在 `code/` 与 `docs/` 里只出现在题面包中（`grep` 可验），所以被测者读不到答案。

### 1.2 隔离与判据

三次生成各在一个空目录里进行，只给该目录的题面包；显式禁止读取仓库与其它尝试目录。
每次交付一个 `answer.c`，判据是题面里的三条命令（`cc` → 链接 → `./oracle`），
12 条样例一条一个进程。

汇总用同一个量尺：

```sh
sh code/sup/firstpass.sh --packet /tmp/lab/packet <含 attempt-01..03.c 的目录> 5
```

### 1.3 结果

```
第 1 次 attempt-01.c：过 12/12
第 2 次 attempt-02.c：过 12/12
第 3 次 attempt-03.c：过 12/12
first-pass: 第 1 次；pass@1=1 pass@5=1
```

- **pass@1 = 3/3**：三次都是首次提交即全过，没有"第 2 次才改对"。
- 三份 `answer.c` 两两不同，但形状只有两种：一份用三目链一次返回，两份用早返回链；
  后两份之间只差一处换行。**声明约束的是行为，不是形状。**

### 1.4 一个反直觉的观察

`compare-sup.sh` 会把"两份都通过"判成**歧义**。在这个实验里，三份都通过并不是缺陷：
独立作者本来就会写出不同的正确实现。歧义判定的适用范围因此要说清楚 ——
它回答的是"**多份候选里挑一份指定的实现**时，样例够不够分开"，不是"正确实现是否唯一"。
把两者混为一谈，就会把"实现自由"错判成"规格不清"。

## 2. 维护实验：陌生维护者改一条对外承诺（n=1）

### 2.1 需求与环境

给一份完整仓库副本（去掉 `.git` 与 `.build`，避免历史与构建产物泄题）与一句需求：

> 服务对"未声明的 HTTP 动词"目前返回 405。改成 501。实现、验收表里相关断言的期望值、
> `DP_GOALS` 的目标措辞要一起维护；不允许删除或放宽断言来变绿。

维护者不知道改动会落在哪些文件，也没有本轮的对话上下文。

### 2.2 结果

| 项 | 实测 |
| --- | --- |
| 改动文件 | 5 个（`rt_http.c`、`blobd.c`、`accept-table.sh`、`SPEC.md`、`VALIDATION.md`） |
| 改动行 | 9 加 / 9 删（18 个 +/- 行） |
| 断言 | 仍是 26 条；#16/#17/#18 期望改为 501，空 body 与无 ETag 两条硬证据原样保留 |
| 全量检查 | `check.sh --full` → **10 项全绿**（含 26 断言、13 变异、14 破坏） |

### 2.3 这次改动暴露的结构

405 的产生点在**运行时**（`rt_http.c` 的 tag → 状态码映射），不在决定层。
所以样例碰不到它，唯一证据是 wire 断言 #16–#18；目标文本也必须同步，否则契约与实现漂移。
这正是 SPEC §5 第 4/5 条说的边界：**判断搬出来了，映射还在运行时**。
18 个 +/- 行也比 `maint-cost.sh` 里"改默认端口 2 文件 / 4 行"大一个量级 ——
维护成本取决于改动落在哪一层，不是常数。

## 3. 复现

```sh
# 作者实验：出题 -> 交给任意模型写 answer.c -> 收成 attempt-01..N.c -> 量
sh code/sup/lab/make-packet.sh /tmp/lab/packet
sh code/sup/firstpass.sh --packet /tmp/lab/packet /tmp/lab/attempts 5

# 维护实验：复制仓库（去掉历史与构建产物），给需求，改完跑
sh code/sup/check.sh --full
```

## 4. 这些数字不能证明什么

1. **任务是决定层，不是完整服务**。路由表、handler、运行时接线怎么从声明生成，本轮没有题面，也没有测量。
2. **样本极小**：作者 n=3，维护 n=1；没有置信区间，不能外推到"AI 一般能写对多少"。
3. **同族模型**。三次生成与维护者来自同一部署配置，不是多模型对比；换模型结果会变。
4. **没有人类维护者**。§2 的"陌生"指没有本轮对话上下文，不是"人类工程师"。
5. **pass@1 的口径是"首次提交即全过"**，不含"跑一次检查后再改"的轮次；真实回路允许迭代。
6. **题面是我写的**。样例覆盖到哪里，实验就只测到哪里；样例之外的行为仍然是猜（§1.4 的歧义边界）。
