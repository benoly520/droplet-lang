# 方案 B：C 不换，加一层"义务清单 + 对账器"（一页设计，v0.29）

> 这是作者那句"为什么不直接用 C"的**最强版本**：不动编写语言，只补一层机器可查的约定。
> 本轮只出设计 + 一个 45 行的原型（`surface-c.py`），**不改 `code/lang`，不占 H8 预算**。
> 结论先放这里：B 能做到 ①②④ 的**报告**，做不到 ① 的**拦截**，也完全不解 7.4 那条
> （目标与实现之间没有会失败的通路）。判据写在 §4，用来决定要不要继续投 B。

## 1. 三层，成本与能力各自独立

| 层 | 做法 | 实测/预估成本 | 能拦什么 | 拦不住什么 |
| --- | --- | --- | --- | --- |
| **L1 文本模式** | 清单（`manifest.json`）+ 正则抽取源码里的路由 / 成功码 / 环境变量名，对账 | **45 行**，本轮已跑 | 漏报"代码里有、清单没写 `DP_LOG_LEVEL`"（退出码 1） | **一次普通重构就穿**：同一处读取改成 `snprintf("%s%s%s", "DP_","LOG_","LEVEL")` 再 `getenv(nm)`，对账报全对得上（rc=0），二进制照读（VALIDATION §7.3-②） |
| **L2 语义层** | libclang / clang 插件 / clang-tidy 自定义 check：走 AST，抽 `CallExpr`、字符串常量折叠、控制流；顺带把"每个写路由必须过一次 `dp_precondition_check`"做成一条 check | 未实测。clang 插件开发 + 维护一个 AST 访问器，**与写一个小型 front-end 同量级**；且要接进 CI 就得管编译数据库（`compile_commands.json`） | 拼接名、间接调用、经 `environ` 的读取 —— L1 那三个洞 | **状态语义**：`fs.create()` 的 bool 被丢弃这类事，任何模式/AST 检查都只能提示"返回值没用"，不能知道它违反了"POST 只在 key 不存在时成功" |
| **L3 结构强制** | 路由表、守卫插入点、配置加载从清单**生成**（人不手写 dispatcher） | 这就是现在那 247 行生成代码 + `gen` 包 | "漏写"与"决定不写"分成两个状态（VALIDATION §7.3-①）；`env` 未声明就读不到（§7.3-② droplet 侧） | —— L3 已经是这门语言本身 |

一句话：**B 的天花板就是 L2，而 L2 的成本与收益最后会走到 L3。**
本轮新拿到的是这条判据的实测版本：L1 便宜（45 行）但可被普通重构击穿；
L3 才给到"结构性闭合"；L2 是那条还没量过的中间路。

## 2. 清单该长什么样（照 `droplet contract` 已有的形状抄，不是新发明）

`droplet contract` 导出的四节正好就是清单的内容，所以两边可以共用一个 schema：

```json
{
  "boundaries": [{ "name": "BlobApi", "version": 1, "methods": [{
      "verb": "PUT", "path": "/v1/blob", "impl": "blob_put",
      "idempotent": true, "precondition": true, "success": 204,
      "intents": [{ "kind": "invariant", "text": "PUT 前必须存在上一版本快照" }]
  }]}],
  "envs": [{ "name": "App", "prefix": "APP", "keys": [
      { "name": "root", "type": "str", "var": "APP_ROOT", "required": true } ]}],
  "tags": [{ "name": "NotFound", "value": 100 }],
  "functions": []
}
```

本轮实测的对照物：手写 C 那份清单我写了 5 条路由 / 4 个成功码 / 5 个环境变量名（`manifest.json`，5 行）。
差别不在字段，在**谁产生这份清单**：语言侧由源码导出（所以它与实现不可能漂移，导出格式本身另有
`internal/contract/doc_test.go` 的 `TestWebapiContract` / `TestEnvExport` / `TestTagNumbers` 钉着），
B 侧由人手写（于是它自己也要一条通路来验它跟代码一致 —— 那条通路就是 L1/L2，也正是 7.3-② 里被击穿的东西）。

## 3. B 解不了的那一条，与 A 一样解不了

**VALIDATION §7.4**：`invariant "POST 只在 key 不存在时成功"`，语言版回 201，C 对照组回 409。
B 的清单里同样可以写 `"intents": [{"text": "POST 只在 key 不存在时成功"}]`，但对账器读完这段中文之后**没有任何动作可做**。
要让它有动作，只有三条路，且三条都和 A 面对的一样：

1. 把意图降成纯谓词 + `example`（就是 `intents.dlt` 现在做的）——**但它验的是复制品，不是实现**；
2. 给 `env` / host 能力做**可验证的替身**，让 handler 的样例不跑服务也能求值（P12 的路 b，与 D0「不把工具变成服务运行器」要正面谈一次）；
3. 把验证挪到运行时之前，做成 wire 级契约测试（`accept-c.sh` 这类）——**它靠人想到那一条**，
   本轮实测：19 条断言里没有"同一 key POST 两次"，所以三层一起漏。

**所以 A/B 的真实分歧点不在能不能拦纪律 ①②④，而在同一条链上谁更便宜地走到 2。**
这条是下一轮该拍的板，也决定了 P12 该按哪条路做。

## 4. 什么情况下该改投 B（可证伪的判据，先写死）

以下三条**同时**成立才谈改投，否则 A 继续：

1. L2 原型能在**拼接名**、`environ` 直读、间接调用三个例子上全部拦住（各造一个真实样本，不许口头说）；
2. L2 的代码量与维护成本实测低于 `gen` 包当前规模（`gen` 非测试 Go **1018** 行；
   `code/lang` 全部非测试 Go 6521 行，H8 余量 7 行）；
3. 意图→实现那条通路（§3 第 2 或第 3 条）在 B 下比在 A 下**更便宜** —— 注意本轮的证据指向相反方向：
   复制品验不出实现，A 至少有"样例写在被调用那一侧"这一点。

第 1 条是唯一还没量过的东西。若要量，代价是一个 clang 插件 demo（约 200 行 C++/Python，
在 `code/lang` 之外，不占 H8）——**登记为 P17，优先级低于 P12**，
因为 §3 已经说明：拦住 ② 不能补上 7.4 那个洞。
