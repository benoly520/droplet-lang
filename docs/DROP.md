# DROP.md —— 一门真的重写的极简语言：`drop/`

本篇只讲一件事：用户说「让你实现一门极简新语言，能不能不要参考以前的所有文档；现在实现了个啥，你自己看看」。
我看了，然后当场认错：**v0.38 交上去的 `lang/*.dpt` 不是一门语言，是一份登记格式**。证据不是感觉：

- `dpt-check.py` 要读 `req/{SRC,REQ,TRANS,AMBIG,GAP}` 五份表、`code/webapi/deploy/accept-table.sh`、
  `code/sup/mutation-score.py`、`blobd --contract` 才能工作 —— 离开这些它什么都判不了；
- 一个「算 1+1 并打印」的 `.dpt` 程序会被 E07 直接拒（没有 `service`、没有承诺）；
- 它的合法输入形状就是那五份表的形状，也就是说它是**表的另一种排版**，不是新的表达能力。

那一版留在那里没删，去留是三选一（转正 / 补齐证据 / 关掉），**这个裁决权在用户**（见 NEXT.md P1b）。
`drop/` 不参与那个裁决：它从零开始，**不引用仓库里任何其它文件**（本篇也不属于它的输入 —— 下面会验）。

## 0. v0.40 用户提的两条

本轮用户说的是：「语法 API 越简单越好。比如循环只能有一种用法，不需要任何语法糖，不需要也不能自动
隐式转换，让 AI 在使用中遇到的问题只有唯一一种方案，没有多选。还有，我希望你用这门新语言实现一个
最简单的 HTTP 服务器，支持简单的 HTTP 请求。」

这两条不是"再加功能"，是**再删**：v0.39 还留着 `map/filter/fold/range/sort`、表达式体函数、匿名函数、
`print` 的隐式转换 —— 每一个都是"第二方案"。v0.40 把它们全删了，然后拿一个真服务器验收
（删完还能写出能跑的东西，才算删对）。§3 讲删了什么、怎么锁住，§7 讲那个服务器。

## 1. 什么叫"不参考以前的文档"

`drop/` 里只有五样东西，语言的全部就这些：

| 文件 | 角色 | 本轮实测 |
| --- | --- | --- |
| `drop/spec.txt` | 唯一定义，读这一页就会写程序 | 150 行 / 11,347 B / 1,750 token（估算）≤ 预算 1,750，占用 **100.0%** |
| `drop/drop.py` | 参考实现（Python，解释执行） | 1,194 行；定义里 14 条码 = 实现会吐的 14 码，逐一对上 |
| `drop/check.sh` | 五段门 + 十一条破坏 | 全绿，2.5 秒（连跑三遍 2539 / 2467 / 2518 ms） |
| `drop/examples/*.dr` | 6 份例子（作者写的） | 4 份输出逐字对得上 `*.out`（第 1 段）、`http.dr` 拿真 socket 打（第 5 段）、`spec.dr` 是从定义里抽出来的（第 4 段） |
| `drop/tests/*.dr` | 4 份程序（**冷读读者**只读定义写的） | 一次跑通 4/4（为 v0.40 改写过，见 §5） |

`grep -rnE '([r]eq|[c]ode|[d]ocs|[l]ang)/|[.]dpt|[b]lobd|[S]PEC' drop/` 命中 0 处。
本轮起这条**不再是文档里手写的一句 grep**：它进了门的第 1 段，并且有一条 Z11 破坏盯着它 ——
往定义里塞一句"去别处看"，门当场红（本轮真发生过一次：实现的注释里写了仓库别处的目录名，那时候什么都不会红）。

语言本身很短：值六种（整数 / 字符串 / true / false / none / 表），句式三种（`let` / `fn` / 表达式），
内置只有 9 个（`print len str num bytes split join serve reply`）。没有赋值，所以没有会变的状态；
循环只剩尾递归；`abs`、元组、多返回值仍然没有 —— 缺什么是明写的，不是等读者撞上去才发现。

## 2. 怎么写一个程序（本轮之后只剩一条路）

```drop
// 数到 n 的和：唯一的循环 = 尾位调用自己
fn sum(n, acc) { if(n <= 0, acc, sum(n - 1, acc + n)) }
print(str(sum(100, 0)))                  // 5050 —— print 只吃字符串，所以必须套 str

// 按空格切一句，数有几个词：没有 map / filter，自己扫
fn words(s, sep, i, acc) {
  if(i >= len(s), acc, if(s[i] == sep, words(s, sep, i + 1, acc + 1), words(s, sep, i + 1, acc)))
}
print(str(words("a b c", " ", 0, 1)))    // 3
```

```sh
python3 drop/drop.py 你的程序.dr
```

上面这两段没有一处"还可以这么写"：不能写 `for i in range(100)`（`range` 不存在，占这个名字 = E3），
不能写 `fn f(x) = x + 1`（函数只有一种写法），不能把 `sum` 当值递给别的函数，不能 `print(1)`。

## 3. v0.40：同一件事只许有一种写法

用户要的是「没有多选」。做法不是加约束，是把第二条路**从语言里删掉**，删完还不许实现偷偷留着 ——
四组东西，每组都有门盯着：

| 被删掉的第二方案 | v0.40 唯一的写法 | 写了删掉的那种会怎样 |
| --- | --- | --- |
| `while` / `for` / `break` / `continue` / `return` / `else` | 函数在**尾位**调用自己 | 这 6 个名字是保留名，占了 = **E3** |
| `range` / `map` / `filter` / `fold` / `sort` | 同上（自己写带 acc 的尾递归） | 这 5 个名字也是保留名：调用 = **E3**，**自己定义一个叫 `map` 的函数也是 E3** —— 后门一并焊死 |
| 表达式体 `fn f(x) = e`、匿名函数、把函数当值递 | 函数只有一种写法：名字 + 形参 + 块 | 调用目标必须是裸名字；把绑着的函数当值读出来 = **E3** |
| `print(1)` 之类的隐式转换 | 上屏幕只有 `print(str(x))` | `print` 只收字符串，别的种类 = **E10** |

最后一行有个副产品，值得单独说：隐式转换删掉之后，**格式规则从两套变成一套**。v0.39 里 `print` 打表
和 `str` 打表是两处代码两处规则（N1 那个洞就是这么来的）；现在 `print` 只吃字符串，屏幕上只可能
出现 `str` 那一种格式，规则重复这件事在结构上没了落脚处。

「尾位」在定义里是死的：函数体块里的最后一句；最后一句是 `if` 时两支里的自身调用都算尾位。
非尾调用仍按 200 层上限报 E13（v0.39 的数，没动），实测 `d(199)` 过、`d(200)` 红，报
「调用叠到第 201 层」。尾调用则是**跳回函数开头**，不涨层数：

```
count(8000000, 0)  →  rc=0，输出 8000000，VmHWM 13,768 KB，18.2 秒
```

八百万次迭代，峰值驻留和一次迭代差不多（同一形状的程序非尾递归在 201 层就红了）。这条不是"设计上支持
尾递归"的声明，是上面这三行数字。

锁住它的不是我的自觉，是三条新破坏：**Z8** 把 `SUGAR` 那五个名字恢复成可调用 → 自测当场红；
**Z9** 把 `print` 的隐式转换恢复回去 → 自测红；**Z10** 让 `serve()` 在没有 `--serve` 时自己挑端口 →
探针立刻看见"它在听"→ 红。顺序仍是先加破坏再定规则，反过来的话破坏测的是不存在的东西。

## 4. 定义即预算，定义即可执行

预算守的是「一遍读得完」这条承诺：`spec.txt` 超预算就红，不是能力上限，是**可读性上限**。
来由写在 `check.sh` 头部注释里：第一版定义 497 token，读者能跑出 3 份程序，同时交回 **25 条「只能靠猜」**
—— 薄不等于好，薄只是没写完。

**本轮动了一次预算，这是本轮唯一一处放宽，写清楚账**：`BUDGET_TOK` 从 1,500 提到 **1,750**，
`BUDGET_BYTES` 从 10,240 提到 **11,900**。不是因为松着好用，是因为定义这次多背了两块内容：
「循环只有一种」要写明尾位的定义和那 11 个「这里没有那种东西」的名字，「跑一个服务器」要把端口来源、
四个头、上限怎么断、处理函数红不红全都写死 —— 这些东西 v0.39 的定义里没有，因为那时候还没这两件事。
第一版重写落地是 1,682–1,766 token，摆在面前只有三条路：把服务器那节挪到别的文档（等于"定义不是全部"，
破掉干净房间那条）、把它写得含糊让读者猜（正是那 25 条靠猜的老病）、抬预算。选了抬预算，
再把散文和样本从 1,766 压到 **1,750**（11,347 B / 150 行，占用 **100.0% / 95.4%**）。
占用到 100% 不是巧合，是本轮已经用掉这个额度一次：写服务器那节时补了两句「实现本来就在做、定义却没说」
的话（绑在 `0.0.0.0`、`Ctrl-C 停`），同比例删掉两句冗余散文才没超 —— 下一个要加的东西必须先删点别的。
这本身是收紧，别把它读成"以后还能加"。
删掉的四个糖、六个循环关键字、`print` 的隐式转换、把函数当值这条路，没有一条趁预算变宽被放回来。

更要紧的一条：**定义里带 `> ` 的行是真代码**。`check.sh` 第 4 段把它们逐行抽成 `examples/spec.dr`，
先跟提交在仓库里的那份**逐字比对**（防止有人改了散文里的代码却没重跑），再跑一遍要求输出等于
`examples/spec.out`。这条是上一轮被读者当场抓出来的：我的定义里举的例**自己就不是合法程序**。
所以这里没有"作者说这是例子"的余地 —— 现在定义里那 **24 行**真代码（v0.39 是 47 行）是机器抽出来
机器跑的，跑出来 **20 行**输出。行数掉一半是 §3 那次删的直接后果：糖少了，例子就少了。

## 5. 三轮冷读的台账

前三节的数字都来自这台机器；这一节记的是"别人只读定义能不能写出来"，那是这门语言真正的成绩，
**第三轮到现在还没跑**（见下面和 NEXT.md 的 P0）。

**第一轮**（新上下文读者，只读 497-token 定义）：3 份程序全跑通、零修改；同时交回 25 条靠猜。
两个事实都记下来：语言能用 ≠ 定义写完了。

**第二轮**（同一读者读修订版定义，这次不许执行）：25 条里 **21 条关闭**，另给 7 个新洞：

| 洞 | 内容 | 本轮处理 |
| --- | --- | --- |
| N1 | `print` 打表不套括号 → `print([1,2,3])` 与 `print([1,[2,3]])` 都是 `1,2,3`，空表打出来是空行 | **作者引进的真缺陷**，认了：`print(x)` 就定义为「写 `str(x)` 再换行」，一条规则 |
| N2 | `str` 对表丢信息：`["a,b"]` 和 `["a","b"]` 都是 `[a,b]` | 表里的字符串元素再套一层引号，现在 `["a,b"]` 与 `["a","b"]` 分得开 |
| N3 | 形参能不能叫 `len` | 不能；`let` 名、`fn` 名、形参名占了内置名/关键字一律 E3 |
| N4 | 块里能不能写 `fn` | 能，块内局部函数；顺带把块当表达式也补齐了（`print({ let a = 1 a + 1 })`） |
| N5 | `map(f, "ab")` 算不算吃字符串 | 不吃，表才行；给字符串 = E5。想要按字符处理就自己切 |
| N6 | `if(c, a)` 少一支是 E2 还是 E3 | E3（`if` 是位置语法，不是函数调用；内置函数的个数不符才是 E2） |
| N7 | 递归上限没有数 | 实现写死 200 层，第 201 层报新码 **E13**；宿主 `RecursionError` 从此不该出现 |

N1/N2 的代价是**数字变大**：`print` 一改，两个例子的期望输出要重写，读者的两份程序输出也跟着变
（它的表打印行原来是 `1,2,3`，现在是 `[1,2,3]`）。这不是放宽，是纠正 —— 它要求的正是「第一个是不是
`1,文,` 结尾带鬼逗号」，实测改前确实是那个样子。

上面这表的「本轮处理」是 **v0.39** 那一轮落地的，v0.40 又往前走了两步，别照抄表里的写法：
N1 现在不再靠"两条规则对齐"，而是 `print` 只收字符串、格式规则只剩 `str` 一套（§3）；
N5 里那个 `map(f, "ab")` 已经无处可报错 —— `map` 这个名字不存在了。表里 N4 那行例子
`print({ let a = 1 a + 1 })` 按 v0.40 的定义是 **E10**，现在要写 `print(str({ let a = 1 a + 1 }))`。

**本轮机械复核**（把读者第二轮交来的 4 份程序逐字搬进 `drop/tests/` 真跑）：

```
对上 tests/reader2_1.dr      # 去重升序：[1,2,3]
对上 tests/reader2_2.dr      # 按空格切串 + 不同词数：["one","two","three","three"] / 3
对上 tests/reader2_3.dr      # FizzBuzz 1..15：15 行逐字对
对上 tests/reader2_4.dr      # 20 以内合数：11 行 + 一行 join
```

四份全是一次跑绿（它自己那两份表打印的期望值随 N1 修复而更新，其余逐行与它的推理一致）。
这就是「不用猜」的机械形式：把别人只读定义写出的程序当回归测试，锁进门里。

**v0.40 对这四份做了什么，必须写清代价**：它们不再是读者的原文。四份里有三份大量使用 `filter` / `fold` /
匿名函数 / `fn f(x) = e`，而那些名字这次被删了 —— 保留原样就是留着四份跑不通的"历史文档"，锁进门里反而
变成假绿。所以每份文件头都写明了"原来那三行是什么、为什么不能照抄、现在只剩哪一条路"（`head -6
drop/tests/reader2_1.dr` 可直接查），输出要求**一字没改**：`[1,2,3]`、四行词数、15 行 FizzBuzz、
11 行合数 + 一行 `join` 全部不变。等价性是拿输出对出来的，不是我说它一样。
代价是：这四份从此**不能当作"读者一次写对"的证据**，只能当作"删糖之后仍能表达同一件事"的回归。
真正的新读者读数仍欠着。

**第三轮还是没跑。** 计划不变：换一个全新上下文的读者、只给 `spec.txt`，再数一次猜的次数。上一轮试过一次，
`create_agent` 被「并发子线程上限 25」拒了；本轮把力气花在删糖和服务器上，没再开线程去撞那堵墙，
所以**本轮结论不来自新读者**，只来自上面这些机械复核 + 旧读者意见的逐条落地。这条欠账记在 NEXT.md 的 P0，
本轮还多欠一条（上面那四份是作者改写过的，不是读者原文）。

## 6. 门与破坏

`sh drop/check.sh` 的五段（实测输出）：

| 段 | 内容 | 本轮数字 |
| --- | --- | --- |
| [1/5] 例子 | `examples/*.dr` + `tests/*.dr` 的实际 stdout 必须逐字等于 `*.out`；`http.dr` 在这段**跳过**（第五段拿真 socket 打它）；另外两条命令行检查：无参数 → 退出码 2、文件不存在 → 退出码 1 且**不吐 Python 堆栈** | 8 份程序对上 + 1 份跳过 + 2 条 CLI 全对上 |
| [2/5] 对账 | 定义 14 码 = 实现 14 码，逐一对上（含名字）；实现的 **128 条**表面每条都能在定义里找到原话；**68 个**样本逐个打中自己声称的那条码 | 绿 |
| [3/5] 预算 | `spec.txt` ≤ 1,750 token / ≤ 11,900 B（本轮抬过一次，账在 §4） | 1,750 / 11,347（100.0% / 95.4%） |
| [4/5] 定义即可执行 | 从定义抽 `> ` 行 → 逐字等于 `examples/spec.dr` → 跑出 `examples/spec.out` | 24 行代码 / 20 行输出 |
| [5/5] 服务器 | 起真进程、拿真 socket 打 `examples/http.dr`，89 行对话逐字对上 `tests/http.expected` | 绿（见 §7） |

表面从 76 条涨到 128 条、样本从 36 个涨到 68 个，是删糖和服务器删出来的账：删一个名字要同时钉住
「占了这个名字 = E3」「调用它 = E3」「定义它也是 E3」三条，再加服务器那一节每条规则一个样本。
门时间从 1.4 秒涨到 **2.5 秒**（连跑三遍 2539 / 2467 / 2518 ms），涨的是第五段真 socket + Z11 那次嵌套跑。

十一条破坏（门自己会不会失效），实测 **11 抓住 / 0 假绿**：

```
抓住 Z1：定义少一条码 -> 对账红
抓住 Z2：实现与定义说得不一样 -> 对账红
抓住 Z3：有条码不再按自己报 -> 活性测试红
抓住 Z4：定义删掉一条规则 -> 表面探针红
抓住 Z5：定义里的例子跑不通 -> 红
抓住 Z6：print 打表的规则被改回去 -> 例子立刻对不上
抓住 Z7：期望输出（*.out）被藏起来 -> 门红，且报的是「缺哪个文件」
抓住 Z8：把 map/filter/fold/range/sort 放回可调用 -> 活性测试红
抓住 Z9：print 恢复隐式转换 -> 活性测试红
抓住 Z10：serve 在没 --serve 时自己挑端口 -> 立刻红（端口只有命令行一个来源）
抓住 Z11：定义里塞一句指向本目录之外的引用 -> 第一段当场红，且报的是独立性
```

Z6 是上一轮加的，专门盯 N1。Z8/Z9/Z10 是本轮加的，盯的是本轮那三条"只有一种写法"：
**如果一种收紧只能靠我下次记得，那它就没有存在过** —— 所以每一条删除都要有一条能把删除撤销掉的破坏，
撤销之后门必须当场红。

Z7 也不是凭空加的 —— 加它之前这条洞是真的存在：仓库根 `.gitignore` 里有一条 `*.out`（本意是 C 的
`a.out`），把 `drop/` 的期望输出全吞了。`git ls-files` 里 0 个 `.out`，也就是说**本地跑多少遍都是绿，
干净克隆里第 1 段根本没跑**。这一条是在提交前的自我复核里发现的（`git status` 里 `.out` 一个都没列出来），
不是 CI 抓的，别记成 CI 的功劳。修法两处：`.gitignore` 给 `drop/**/*.out` 开例外，门里加 Z7 ——
把整棵树拷到临时目录、删掉所有 `.out`、在那儿重跑一遍 `check.sh`，要求它必须红、必须说清缺哪个文件、
并且不许吐 Python 堆栈。同一轮还顺手把行数报错了：门用 `换行数 + 1` 数行，文件以换行结尾时多报一行，
`spec.txt` 那时实际 **152 行**（此前文档写的 153 是这个 off-by-one 的产物，属于数字写错）。本轮重写后
是 **150 行**，这条数法已改成直接数，不再 `+1`。

**本轮 Z7 自己漏过一次，也记下来**：加了 `examples/http.dr` 之后 Z6（临时树里逐份跑例子）撞上一条

## 7. 用它写了个真 HTTP 服务器

用户第二条要求。跑法只有一条（定义里也是这一条）：

```sh
python3 drop/drop.py --serve 8087 drop/examples/http.dr   # 然后 curl http://127.0.0.1:8087/
```

`examples/http.dr` **23 行**，里面能看到的构造只有：`fn`、`if`、`let`、`split`、`str`、`==`、`||`、
下标、切片、`reply`、`serve`。路由就是一层一层的 `if`，没有路由表、没有框架、没有装饰器 —— 定义里
明写了「除 status、body、端口外没有任何可配的东西」。它支持的：`GET` / `HEAD` 走路径（`/` 打 pong、
`/peer` 打对端地址、`/len` 打请求字节数、`/ver` 打请求行、其余 404），`POST` 把请求体原样回出去，
其它方法 405。

设计上每一次"只留一个来源"都是这么落的，每一条都有码钉住：

| 决定的东西 | 只留的那一个 | 想走第二条会怎样 |
| --- | --- | --- |
| 端口从哪来 | `--serve <port>`，只有命令行（地址固定 `0.0.0.0`，没有可配项） | `serve()` 不收参数；程序里没写 `--serve` 却调它 = **E14**（Z10 盯这条） |
| 处理函数是谁 | 固定名字 `fn handle()` | 没有 = **E1**；接了参数 = **E2**；`serve()` 不是最后一句 = **E3** |
| 请求怎么进程序 | 只读名 `request`、`peer` | 程序绑不出也改不了；没见过请求就读它 = **E14** |
| 响应怎么出去 | `reply(status, body)`，头固定四行 | 一次请求调两次 = **E14**（「一次请求只有一个响应」） |
| 正文怎么变字节 | 复用 `bytes()` 那一条规则 | 没有第二条编码路；这也是"请求体原样回出去还是那些字节"能成立的原因 |
| 行分隔符 | 只认 CRLF | 只写 LF 的请求不认，**直接断连接**，不是错误码 |
| 超限 / 空闲 | 64 KiB 首部、1 MiB 正文、10 秒没动静 → 断这条连接 | 同样不是错误码：这不是程序写错，是网络 |
| 程序里报错了 | 整个服务器一红就停 | 服务器不兜程序的错 —— 兜了就得再加一套"错误怎么变状态码"的规矩，那是第二个方案 |

验收不是"我试过了能通"，是 `tests/http_check.py` 用**裸 socket** 打真进程，把 89 行对话
（`tests/http.expected`）逐字钉住：每个响应行、`Date:` 归一化成 `*`、`127.0.0.1:<port>` 归一化成 `*`，
连「回来的最后 11 个字节和发出去的一模一样吗 → True」这一句断言本身也在台账里。跑法：`sh drop/check.sh`
第五段；单独跑 `python3 drop/tests/http_check.py <空闲端口>` 也行（它自己起服务器自己收，实测和门里的
台账 `diff` 为空）。

本轮在这个服务器上抓到的六个真问题，都记下来，因为它们都是"看起来能跑"掩盖的：

1. **`bytes()` 和实现说的不一样**。定义写「每个字符取其码，<=255 就是一个字节，更大的拆成 UTF-8」，
   实现原先一律 UTF-8 编码，于是 `bytes("ä")` 定义是 1 个字节、实现是 2 个。这是表面探针测不出来的
   （它只查"定义里有没有这句话"），补的是一个活样本：`print(str(len(bytes("\xe4"))))` → `1`。
2. **POST 回声是乱码**。`reply` 走 `body.encode("utf-8")`，而 `request` 是一字节一字符的 latin-1 串 ——
   两条编码路，正好违反本轮自己那条原则。合并成共用 `_wire()` 之后回声才是字节透明的。
3. **门曾经卡 5 秒**。客户端只发 LF 结尾的请求时，服务器在等更多首部字节，探针在等响应，两边都不肯先走。
   根因就是"行分隔只认 CRLF"这一条没配一个"死等多久"的数 —— 加了 `IDLE_SEC = 10` 直接断连，探针改成
   半关闭（`shutdown(SHUT_WR)`）。门时间从 7–8 秒回到 2–3 秒，**台账文本一字没变**。
4. **实现说了、定义没说**（写这一段时才发现的）。实现里 `sock.bind(("0.0.0.0", port))`、`Ctrl-C` 直接退，
   两句都是真行为，定义里一个字都没有 —— 按 §4 的纪律，实现做的每件事都得能在定义里找到原话，否则
   读者猜的就是"还有多少没写的"。补进定义（并加两条表面探针钉住），代价就是预算当场顶到 100.0%。
5. **破坏测试会假装成功**（§6 里 Z7/Z6 那段），起因就是给门加了这份新例子。
6. **「不引用仓库别处」这句独立性，当时还只是文档里手跑的一条 grep**：写 §1 的时候顺手在实现的注释里指了一句
   仓库别处的目录名 —— 那句话让「读这一页就会用」当场不成立，而本地、CI、文档里那句 grep 谁都没红（模式恰好
   不包含那个目录名）。引用已删，检查本身则进了门的第 1 段 + Z11；教训是**判据不能停在文档里**（§6 末段）。

## 8. 这门语言不解决什么

说清楚边界，免得下一篇又写成"顺手解决了工程问题"：

- `drop` 是**计算语言**：写程序、算东西、打印，外加一个最小程序服务器。它不登记承诺、不认识断言编号、
  不引用变异表 —— 也就是说 v0.38 想解决的「需求↔证据失联」它一条都没解决，那是 `lang/` 那条路的事
  （尚未裁决）。
- 没有赋值 → 没有可变状态。循环只有尾递归一种，**转**不限层数（实测 800 万次），**往里缩**由 E13 限在
  200 层。这是设计取舍，不是疏忽；代价是每个"扫一遍表"都得手写一个带 acc 的具名函数。
- 那个 HTTP 服务器是**最小**的，不吹：单线程顺序 accept（一次只服务一条连接）、HTTP/1.1 但只回四个头、
  没有 TLS、没有 chunked、没有路由表、状态原因短语由宿主给、程序报错直接停。它证明的是"这门语言写得出
  真网络程序"，不是"可以拿去上线"。
- 参考实现 1,194 行 Python，不追求性能、不产生字节码、没有标准库；除了那 9 个内置，什么都没有。
- 错误码穷举意味着「没有第 15 种」是能测的（`--self-check` 双向比），但穷举的是**这个实现**会吐的码，
  不是所有可能的错误；比如 OOM、磁盘满仍然归宿主，定义里明写了「宿主栈崩不算实现的一部分」。
  连接被断、超限、超时**故意不占码** —— 它们不是程序的错，给它一个 E 码就是多造一个"看起来像 bug"的出口。

## 9. 一句话结论

`lang/` 是不是语言，判据是它能不能离开仓库里那五份表 —— 不能。
`drop/` 是不是语言，判据是能不能离开 `drop/` 自己 —— 现在 0 处引用、五段门 + 十一条破坏全绿、定义顶满预算、
读这一页就能起一个真 HTTP 服务器。**本轮用户要的两件事都落地了**：删完之后只剩唯一一种写法（每条删除
配一条能把删除撤销掉的破坏测试），而且这门语言写得出让真 socket 打的程序。

还欠的两笔，别混着说：新读者的第三次读数没跑（P0），而且本轮把读者的那 4 份程序改写成了作者的写法 ——
它们现在是"删糖后仍能表达"的回归，不再是"读者一次写对"的证据。**那一轮的猜中率才是这门语言的分数。**
