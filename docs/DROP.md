# DROP.md —— 一门真的重写的极简语言：`drop/`

本篇只讲一件事：用户说「让你实现一门极简新语言，能不能不要参考以前的所有文档；现在实现了个啥，你自己看看」。
我看了，然后当场认错：**v0.38 交上去的 `lang/*.dpt` 不是一门语言，是一份登记格式**。证据不是感觉：

- `dpt-check.py` 要读 `req/{SRC,REQ,TRANS,AMBIG,GAP}` 五份表、`code/webapi/deploy/accept-table.sh`、
  `code/sup/mutation-score.py`、`blobd --contract` 才能工作 —— 离开这些它什么都判不了；
- 一个「算 1+1 并打印」的 `.dpt` 程序会被 E07 直接拒（没有 `service`、没有承诺）；
- 它的合法输入形状就是那五份表的形状，也就是说它是**表的另一种排版**，不是新的表达能力。

那一版留在那里没删，去留是三选一（转正 / 补齐证据 / 关掉），**这个裁决权在用户**（见 NEXT.md P1b）。
`drop/` 不参与那个裁决：它从零开始，**不引用仓库里任何其它文件**（本篇也不属于它的输入 —— 下面会验）。

## 0. 用户提的三条：前两条落在 v0.40，第三条是 v0.41 的全部

v0.40 用户说的是：「语法 API 越简单越好。比如循环只能有一种用法，不需要任何语法糖，不需要也不能自动
隐式转换，让 AI 在使用中遇到的问题只有唯一一种方案，没有多选。还有，我希望你用这门新语言实现一个
最简单的 HTTP 服务器，支持简单的 HTTP 请求。」

这两条不是"再加功能"，是**再删**：v0.39 还留着 `map/filter/fold/range/sort`、表达式体函数、匿名函数、
`print` 的隐式转换 —— 每一个都是"第二方案"。v0.40 把它们全删了，然后拿一个真服务器验收
（删完还能写出能跑的东西，才算删对）。§3 讲删了什么、怎么锁住。

v0.41 用户否掉的是第二条的**落法**：「不是，HTTP 不应该是这门语言的本身，而是使用这门语言实现的一个
mini Web 服务器，支持 HTTP。就好比 C# 和 Web API。明白吗？」这句点破的是 v0.40 犯的错：我把协议写进了
语言 —— `serve`、`reply` 两个内置名加一个只读名 `request`，11 条协议规则占着定义，那等于让 C# 内嵌
Web API。这一轮的刀法是把 HTTP **请出定义**，落成四层，每层只认自己那一层的东西：

| 层 | 认识什么 | 在哪 |
| --- | --- | --- |
| 语言 | 纯计算，加一个口子 `host(命令, 参数)`（进出都是字符串） | `spec.txt` —— 协议词汇 **0 处**，「请求」只出现在一句否定里 |
| 库 | HTTP：CRLF、Content-Length、keep-alive、状态行与四个头 | `lib/http.dr`，**173 行全是用 drop 写的** |
| 程序 | 路由与响应 | `examples/http.dr`，**20 行** |
| 宿主 | 唯一碰 socket 的地方，七个命令：`bind accept recv send peer close date` | `drop.py` 里那一段 |

同一轮用户还问了一句：「还有，这门新语言不需要编译的吗？直接 Python 环境执行？」—— 对，没有编译这一步：
参考实现就是树遍历解释器，`python3 drop/drop.py 你的程序.dr` 是运行，不产生字节码也不产生品。v0.40 把
这句藏在"服务器的跑法"里，读起来像语言有个编译命令；现在它写在定义的「宿主」一节，说的是**宿主怎么起**，
和语言认识什么无关。§7 讲这四层怎么分、分完当场抓出七个真问题；§4 讲预算因此从 1,750 退回 1,500 ——
那是本轮唯一一处收紧，方向和 v0.40 那次放宽相反。

## 1. 什么叫"不参考以前的文档"

`drop/` 里只有六样东西，语言的全部就这些：

| 文件 | 角色 | 本轮实测 |
| --- | --- | --- |
| `drop/spec.txt` | 唯一定义，读这一页就会写程序 | 135 行 / 9,816 B / **1,498 token**（估算）≤ 预算 1,500，占用 **99.9%** |
| `drop/drop.py` | 参考实现（Python，解释执行，无编译） | 1,155 行；定义里 14 条码 = 实现会吐的 14 码，逐一对上；123 条表面、65 个样本、宿主命令表双向比 |
| `drop/lib/http.dr` | **用 drop 写的 HTTP 库**（不是语言的一部分） | 173 行；只用宿主那七个命令（门第 5 段扫它，第 2 段双向比那张表） |
| `drop/check.sh` | 五段门 + 十四条破坏 | 全绿，9.2 秒（连跑三遍 9155 / 9131 / 9290 ms；涨的账在 §7 末） |
| `drop/examples/*.dr` | 6 份例子（作者写的） | 4 份输出逐字对得上 `*.out`（第 1 段）、`http.dr` 拿真 socket 打（第 5 段）、`spec.dr` 是从定义里抽出来的（第 4 段） |
| `drop/tests/*.dr` | 4 份程序（**冷读读者**只读定义写的） | 一次跑通 4/4（为 v0.40 改写过，见 §5） |

`grep -rnE '([r]eq|[c]ode|[d]ocs|[l]ang)/|[.]dpt|[b]lobd|[S]PEC' drop/` 命中 0 处。
本轮起这条**不再是文档里手写的一句 grep**：它进了门的第 1 段，并且有一条 Z11 破坏盯着它 ——
往定义里塞一句"去别处看"，门当场红（本轮真发生过一次：实现的注释里写了仓库别处的目录名，那时候什么都不会红）。

语言本身很短：值六种（整数 / 字符串 / true / false / none / 表），句式三种（`let` / `fn` / 表达式），
内置只有 8 个（`print len str num bytes split join host`）。没有赋值，所以没有会变的状态；
循环只剩尾递归；`abs`、元组、多返回值仍然没有 —— 缺什么是明写的，不是等读者撞上去才发现。
`host` 是这 8 个里唯一"问外面要东西"的，其余 7 个都只碰值本身。

## 2. 怎么写一个程序（本轮之后只剩一条路）

```drop
// 数到 n 的和：唯一的循环 = 尾位调用自己
fn sum(n, acc) { if(n <= 0, acc, sum(n - 1, acc + n)) }
print(str(sum(100, 0)))                  // 5050 —— print 只吃字符串，所以必须套 str

// 按空格切一句，数有几个词：没有 map / filter，自己扫
fn words(s, sep, i, acc) {
  if(i >= len(s), acc, if(s[i] == sep, words(s, sep, i + 1, acc + 1), words(s, sep, i + 1, acc)))
}
print(str(words("a b c", " ", 0, 1)))    // 3
```

```sh
python3 drop/drop.py 你的程序.dr
```

上面这两段没有一处"还可以这么写"：不能写 `for i in range(100)`（`range` 不存在，占这个名字 = E3），
不能写 `fn f(x) = x + 1`（函数只有一种写法），不能把 `sum` 当值递给别的函数，不能 `print(1)`。

## 3. v0.40：同一件事只许有一种写法

用户要的是「没有多选」。做法不是加约束，是把第二条路**从语言里删掉**，删完还不许实现偷偷留着 ——
四组东西，每组都有门盯着：

| 被删掉的第二方案 | v0.40 唯一的写法 | 写了删掉的那种会怎样 |
| --- | --- | --- |
| `while` / `for` / `break` / `continue` / `return` / `else` | 函数在**尾位**调用自己 | 这 6 个名字是保留名，占了 = **E3** |
| `range` / `map` / `filter` / `fold` / `sort` | 同上（自己写带 acc 的尾递归） | 这 5 个名字也是保留名：调用 = **E3**，**自己定义一个叫 `map` 的函数也是 E3** —— 后门一并焊死 |
| 表达式体 `fn f(x) = e`、匿名函数、把函数当值递 | 函数只有一种写法：名字 + 形参 + 块 | 调用目标必须是裸名字；把绑着的函数当值读出来 = **E3** |
| `print(1)` 之类的隐式转换 | 上屏幕只有 `print(str(x))` | `print` 只收字符串，别的种类 = **E10** |

最后一行有个副产品，值得单独说：隐式转换删掉之后，**格式规则从两套变成一套**。v0.39 里 `print` 打表
和 `str` 打表是两处代码两处规则（N1 那个洞就是这么来的）；现在 `print` 只吃字符串，屏幕上只可能
出现 `str` 那一种格式，规则重复这件事在结构上没了落脚处。

「尾位」在定义里是死的：函数体块里的最后一句；最后一句是 `if` 时两支里的自身调用都算尾位。
非尾调用仍按 200 层上限报 E13（v0.39 的数，没动），实测 `d(199)` 过、`d(200)` 红，报
「调用叠到第 201 层」。尾调用则是**跳回函数开头**，不涨层数：

```
count(8000000, 0)  →  rc=0，输出 8000000，VmHWM 13,768 KB，18.2 秒
```

八百万次迭代，峰值驻留和一次迭代差不多（同一形状的程序非尾递归在 201 层就红了）。这条不是"设计上支持
尾递归"的声明，是上面这三行数字。

锁住它的不是我的自觉，是三条破坏：**Z8** 把 `SUGAR` 那五个名字恢复成可调用 → 自测当场红；
**Z9** 把 `print` 的隐式转换恢复回去 → 自测红；**Z10** 让 `host("bind", "")` 在没给 `--port` 时自己挑一个
端口 → 那条 E14 样本当场不报，活性测试红。顺序仍是先加破坏再定规则，反过来的话破坏测的是不存在的东西。
（Z10 这一条 v0.41 重写过一次：v0.40 它是靠"实现自己往 stderr 打一行『在听』"来判断的，而那行 banner
在 v0.41 已经不属于宿主了 —— 现在钉它的是样本，不是打印。）

## 4. 定义即预算，定义即可执行

预算守的是「一遍读得完」这条承诺：`spec.txt` 超预算就红，不是能力上限，是**可读性上限**。
来由写在 `check.sh` 头部注释里：第一版定义 497 token，读者能跑出 3 份程序，同时交回 **25 条「只能靠猜」**
—— 薄不等于好，薄只是没写完。

**v0.40 抬过一次预算，v0.41 又把它退回来了，两次都写清楚账**。v0.40 把 `BUDGET_TOK` 从 1,500 提到
**1,750**、`BUDGET_BYTES` 从 10,240 提到 **11,900**，理由是定义那次多背了两块内容：「循环只有一种」要写明
尾位的定义和那 11 个「这里没有那种东西」的名字（这块留下来了），「跑一个服务器」要把端口来源、四个头、
上限怎么断、处理函数红不红全都写死（这块就是 v0.41 用户指出来放错地方的东西）。第一版重写落地是
1,682–1,766 token，当时摆在面前只有三条路：把服务器那节挪到别的文档（等于"定义不是全部"，破掉干净房间
那条）、把它写得含糊让读者猜（正是那 25 条靠猜的老病）、抬预算 —— 选了抬预算，代价是此后每加一句都得
当场删一句。

v0.41 做的事就是把协议从定义里搬进 `lib/http.dr`，**预算当场退回 1,500 / 10,240，一句放宽没留**。
现在定义 **1,498 token / 9,816 B / 135 行 = 占用 99.9% / 95.9%**：搬走协议腾出的额度没有拿去加别的说法，
只补了「宿主」这一节（一个口子、七个命令、句柄是字符串、跑法只有一条）。这是本轮唯一一处收紧，方向和
上一轮相反 —— 读数从 1,750 变到 1,498 不是"能力变弱了"，是同一句话挪了家：**定义少了 252 token，
语言少了 0 个构造，库多了 173 行**。剩下那 2 token 的余量是本轮压散文压出来的，不是留着好用的。

更要紧的一条：**定义里带 `> ` 的行是真代码**。`check.sh` 第 4 段把它们逐行抽成 `examples/spec.dr`，
先跟提交在仓库里的那份**逐字比对**（防止有人改了散文里的代码却没重跑），再跑一遍要求输出等于
`examples/spec.out`。这条是上一轮被读者当场抓出来的：我的定义里举的例**自己就不是合法程序**。
所以这里没有"作者说这是例子"的余地 —— 现在定义里那 **24 行**真代码（v0.39 是 47 行）是机器抽出来
机器跑的，跑出来 **20 行**输出，两个数和 v0.40 一样：搬协议没动到例子，因为协议那节本来就没有 `> ` 行。
行数掉一半是 §3 那次删的直接后果：糖少了，例子就少了。

## 5. 三轮冷读的台账

前三节的数字都来自这台机器；这一节记的是"别人只读定义能不能写出来"，那是这门语言真正的成绩，
**第三轮到现在还没跑**（见下面和 NEXT.md 的 P0）。

**第一轮**（新上下文读者，只读 497-token 定义）：3 份程序全跑通、零修改；同时交回 25 条靠猜。
两个事实都记下来：语言能用 ≠ 定义写完了。

**第二轮**（同一读者读修订版定义，这次不许执行）：25 条里 **21 条关闭**，另给 7 个新洞：

| 洞 | 内容 | 本轮处理 |
| --- | --- | --- |
| N1 | `print` 打表不套括号 → `print([1,2,3])` 与 `print([1,[2,3]])` 都是 `1,2,3`，空表打出来是空行 | **作者引进的真缺陷**，认了：`print(x)` 就定义为「写 `str(x)` 再换行」，一条规则 |
| N2 | `str` 对表丢信息：`["a,b"]` 和 `["a","b"]` 都是 `[a,b]` | 表里的字符串元素再套一层引号，现在 `["a,b"]` 与 `["a","b"]` 分得开 |
| N3 | 形参能不能叫 `len` | 不能；`let` 名、`fn` 名、形参名占了内置名/关键字一律 E3 |
| N4 | 块里能不能写 `fn` | 能，块内局部函数；顺带把块当表达式也补齐了（`print({ let a = 1 a + 1 })`） |
| N5 | `map(f, "ab")` 算不算吃字符串 | 不吃，表才行；给字符串 = E5。想要按字符处理就自己切 |
| N6 | `if(c, a)` 少一支是 E2 还是 E3 | E3（`if` 是位置语法，不是函数调用；内置函数的个数不符才是 E2） |
| N7 | 递归上限没有数 | 实现写死 200 层，第 201 层报新码 **E13**；宿主 `RecursionError` 从此不该出现 |

N1/N2 的代价是**数字变大**：`print` 一改，两个例子的期望输出要重写，读者的两份程序输出也跟着变
（它的表打印行原来是 `1,2,3`，现在是 `[1,2,3]`）。这不是放宽，是纠正 —— 它要求的正是「第一个是不是
`1,文,` 结尾带鬼逗号」，实测改前确实是那个样子。

上面这表的「本轮处理」是 **v0.39** 那一轮落地的，v0.40 又往前走了两步，别照抄表里的写法：
N1 现在不再靠"两条规则对齐"，而是 `print` 只收字符串、格式规则只剩 `str` 一套（§3）；
N5 里那个 `map(f, "ab")` 已经无处可报错 —— `map` 这个名字不存在了。表里 N4 那行例子
`print({ let a = 1 a + 1 })` 按 v0.40 的定义是 **E10**，现在要写 `print(str({ let a = 1 a + 1 }))`。

**本轮机械复核**（把读者第二轮交来的 4 份程序逐字搬进 `drop/tests/` 真跑）：

```
对上 tests/reader2_1.dr      # 去重升序：[1,2,3]
对上 tests/reader2_2.dr      # 按空格切串 + 不同词数：["one","two","three","three"] / 3
对上 tests/reader2_3.dr      # FizzBuzz 1..15：15 行逐字对
对上 tests/reader2_4.dr      # 20 以内合数：11 行 + 一行 join
```

四份全是一次跑绿（它自己那两份表打印的期望值随 N1 修复而更新，其余逐行与它的推理一致）。
这就是「不用猜」的机械形式：把别人只读定义写出的程序当回归测试，锁进门里。

**v0.40 对这四份做了什么，必须写清代价**：它们不再是读者的原文。四份里有三份大量使用 `filter` / `fold` /
匿名函数 / `fn f(x) = e`，而那些名字这次被删了 —— 保留原样就是留着四份跑不通的"历史文档"，锁进门里反而
变成假绿。所以每份文件头都写明了"原来那三行是什么、为什么不能照抄、现在只剩哪一条路"（`head -6
drop/tests/reader2_1.dr` 可直接查），输出要求**一字没改**：`[1,2,3]`、四行词数、15 行 FizzBuzz、
11 行合数 + 一行 `join` 全部不变。等价性是拿输出对出来的，不是我说它一样。
代价是：这四份从此**不能当作"读者一次写对"的证据**，只能当作"删糖之后仍能表达同一件事"的回归。
真正的新读者读数仍欠着。

**第三轮还是没跑。** 计划不变：换一个全新上下文的读者、只给 `spec.txt`，再数一次猜的次数。上一轮试过一次，
`create_agent` 被「并发子线程上限 25」拒了；本轮把力气花在删糖和服务器上，没再开线程去撞那堵墙，
所以**本轮结论不来自新读者**，只来自上面这些机械复核 + 旧读者意见的逐条落地。这条欠账记在 NEXT.md 的 P0，
本轮还多欠一条（上面那四份是作者改写过的，不是读者原文）。

## 6. 门与破坏

`sh drop/check.sh` 的五段（实测输出）：

| 段 | 内容 | 本轮数字 |
| --- | --- | --- |

## 7. HTTP 挪出去了：语言 / 库 / 程序 / 宿主 四层

用户 v0.41 那句是本轮唯一的需求：「不是，HTTP 不应该是这门语言的本身，而是使用这门语言实现的一个 mini
Web 服务器，支持 HTTP。就好比 C# 和 Web API。」现在跑法还是只有一条（写在定义的「宿主」一节里）：

```sh
python3 drop/drop.py --port 8087 drop/lib/http.dr drop/examples/http.dr   # 然后 curl http://127.0.0.1:8087/
```

命令行上写的就是"并起来"的顺序，语言里**没有 `use`**：库在前、程序在后，宿主把两个文件拼成一条长文件再跑。
这不是图省事，是有意不加 —— 多一条 `use` 语法就是给"库能做什么"再多一个来源，而 v0.40 之后这门语言只准
有一种写法。库里的函数在**调用时**才查名字，所以顺序只决定行号、不决定可见性：`examples/http.dr` 最后那句
`http_serve()` 调的是前面那 173 行里定义的函数，行号也从那儿一直数到底（第 174 行开始是程序）。

**程序那 20 行**（`examples/http.dr`）里能看到的构造只有：`fn`、`let`、`if`、`==`、`||`、`str`、`len`，
加上库给的四个名字 `http_serve` / `http_reply` / `http_word` / `http_body`。路由就是一层一层的 `if`，
没有路由表、没有框架、没有装饰器。它支持的：`GET` / `HEAD` 走路径（`/` 打 pong、`/peer` 打对端地址、
`/len` 打请求字节数、`/ver` 打请求行、其余 404），`POST` 把请求体原样回出去，其它方法 405。

**库那 173 行**（`lib/http.dr`）是一行一行用 drop 写的 HTTP：只认 CRLF 的行分隔、手数字符拼出
Content-Length（语言没有 `ord`，所以数字值靠查 `"0123456789"` 这张表的位置）、64 KiB 首部与 1 MiB 正文
两个上限、HEAD 只回头不发正文、keep-alive 连着读第二个请求、`Connection: close` 扫的是首部行而不是请求行、
四个响应头、状态码到原因短语一张表。它伸到外面去的手只有 `host(...)` 这一个，用的七个命令全在定义里。

每一次"只留一个来源"现在落在哪一层，每一条都有东西钉住：

| 决定的东西 | 只留的那一个 | 在哪一层 | 想走第二条会怎样 |
| --- | --- | --- | --- |
| 语言怎么问外面 | `host(命令, 参数)`，字符串进、字符串出 | 语言 ↔ 宿主 | 七个之外的命令 = **E14**（样本 + Z13 盯库） |
| 端口从哪来 | `--port <端口>`，只有命令行（地址固定 `0.0.0.0`） | 宿主 | `bind("")` 时没给 = **E14**（Z10 盯这条） |
| 句柄是什么 | 一个字符串，语言不认识它指什么 | 宿主发、库传 | 自己编一个句柄去 `send` = **E14**（台账里"程序绕过库"那条） |
| 协议词汇在不在定义 | 0 处（`spec.txt` 和 `drop.py` 都算） | 定义 | 往定义塞一个 `HTTP` = 第三段当场红（Z12 盯这条） |
| 处理函数是谁 | 固定名字 `fn handle(req, peer)`，**返回** `[状态, 正文]` | 库 ↔ 程序 | 没有 = **E1**；参数个数不对 = **E2**；交回的不是那张表 = **E5**，红落在库的那一行 |
| 响应怎么出去 | `http_reply(status, body)`，头固定四行 | 库 | 走不出第二次：一次调用只有一个返回值，语言里又没有赋值可以攒响应 |
| 正文怎么变字节 | 复用 `bytes()` 那一条规则 | 库 | 没有第二条编码路；"请求体原样回来还是那些字节"靠的就是这一条 |
| 行分隔符 | 只认 CRLF | 库 | 只写 LF 的请求不认，**直接断连接**，不是错误码 |
| 超限 / 空闲 | 64 KiB 首部、1 MiB 正文（库）；10 秒没动静（宿主的 `IDLE_SEC`） | 库 + 宿主 | 都不是错误码：这不是程序写错，是网络 |
| 程序里报错了 | 整个服务器一红就停 | 宿主不兜 | 兜了就得再加一套"错误怎么变状态码"的规矩，那是第二个方案 |

验收还是"裸 socket 打真进程"，只是被打的东西变了：`tests/http_check.py` 起的是 `lib/http.dr` +
`examples/http.dr` 两份文件，把 **88 行**对话（`tests/http.expected`）逐字钉住。和 v0.40 那 89 行对着看，
改动只有三类，一类一类交代：**(a) 线上字节** —— 每一场请求的响应行、四个头、正文，与 v0.40 **逐字节相同**，
这一条是本轮最重要的证据：协议搬进库之后行为没漂；**(b) harness 自己的说明文字** —— 两行标题改了
（"正文由宿主抹掉" → "正文一个字节都不发"，"正文按 bytes(body) 那条路" → "正文走 bytes 那条路"），因为
做事的人从宿主换成了库；**(c) 报错的场景** —— v0.40 那个"一次请求调两次 reply = E14"的场景整体删掉（9 行），
换进两个新场景（8 行，净差 1 行 = 89 → 88）：程序绕过库自己编句柄去 `send` = **E14**，程序交回的不是
`[状态, 正文]` 而是裸整数 = **E5**、**红的那一行落在 `lib/http.dr` 第 139 行**。第三种红（处理函数里报错 = 整台服务器一红就停，
E6）保留，行号从 v0.40 的"第 1 行"变成"第 174 行"—— 那是拼接后行号从头数到底的结果，见下面第 5 条。
最后这一条是本轮最想看到的：库的错归库、程序的错归程序，分层不是文档里的一句话。单独跑
`python3 drop/tests/http_check.py <空闲端口>` 也行，实测与门里的台账 `diff` 为空。

v0.41 这一轮在"把协议改成用这门语言写"的过程里抓到的七个真问题 —— 前六个是"库写起来才发现"的，
第七个是写文档的时候发现门自己有个洞：

1. **语言没有赋值，所以库不能持有状态。** 第一版库照 v0.40 的形状写成 `fn handle()` 读全局 `request` /
   `peer`，然后在库里往全局 `PEER` / `RESP` 上赋值 —— 当场 **E3**。这不是 bug，是这门语言的结构：
   没有会变的状态就没有赋值。改法是让接口返回一个值：`handle(req, peer)` 交回 `[状态, 正文]`。
   副产品是"一次请求只有一个响应"从一条运行时 E14 变成了**结构上走不出的路**。
2. **尾位是浅的，往 `if` 里再套一层就不算了。** 打 70 KB 首部时当场 `第 60 行 E13 —— is_crlf 往里缩到第
   201 层`。实现只认函数体最后一句是尾调用、以及"最后一句是 `if` 时两支里的自身调用"；把自身调用藏在
   第二层 `if` 里（或藏在块表达式里）就是普通调用，每转一圈加一层。修法是把 8 个扫描函数全改成
   「先算条件，再 `if(该停了, 停, 递归(下一格))`」这一个形状，代价是可读性 —— 这个形状值得进定义。
3. **`send` 只在第一个换行处切一刀。** 我以为正文里可以再放一个哨兵字节，于是发出的是
   `"\n" + body + "\x00"` —— 线上真多出来 `\n\x00` 两个字节。宿主说的"第一个换行切开，换行后面一个字符
   发一个字节"就是字面意思，所以 payload 必须原样是 `head + body`，分隔符只有 `句柄 + LF` 那一个。
4. **`Connection: close` 一开始被我拿去匹配请求行。** 台账里那一场的响应少了 `Connection: close` 一行 ——
   补了 `has_close` / `one_close` 逐行扫首部之后，那一行文本才和 v0.40 的台账**逐字节对上**。这条是台账
   的价值：它比的不是"能通"，是字节。
5. **拼接文件时行号差一。** `run_files` 用 `"\n".join(...)`，而每个文件末尾本来就有换行，于是库和程序
   之间凭空多出一行空行，程序第一行的错报成 175 而不是 174。修成"每个文件先 `rstrip` 掉尾部换行再拼"，
   台账里那两个行号当场降 1 —— **文档、台账、文件三处的行号现在数得通**。
6. **harness 自己会被 RST 打死。** 64 KiB 超限那条连接被服务器直接关掉时，客户端还有没读走的字节，
   `recv` 抛 `ConnectionResetError`，整个门崩在非零退出码上 —— 长得和"抓住了"一模一样。补一条
   `except ConnectionResetError: return b""`（RST 就是"断了"），教训又回到 §6 那句：红必须归因。
7. **门自己有个洞：Z13 只管库，不管口子本身。** 写完 §6 才反应过来 —— 破坏只查"库里有没有用第八个
   命令"，那么**实现的 `HOST_CMDS` 变宽到八个、库里一次都没用**，门照样绿；而定义那句「命令只有七个」
   的探针只看定义里有没有这句话，也拦不住。补法是双向比一次（第 2 段：实现的表 ↔ 定义那七个名字，
   宽了、少了、名字没在定义里出现过，三种都算不拢）+ Z14 把这条纪律钉住。

**分层的价格，也记在这里**：同一台机器上跑同一条台账，v0.40（协议在 Python 里）0.22 秒，v0.41（协议在
drop 里）**4.96 秒**，门总时间从 2.48 秒涨到 9.2 秒。逐条计时之后账很清楚：普通请求（GET / HEAD / POST /
keep-alive / `/peer`）全部 0–1 毫秒，唯一慢的是那条 70,000 字节首部的用例，**单条 4.63 秒** —— 因为
`find_blank` 是一个字符一个字符在解释执行的 drop 里走的。这不是协议变慢了，是"用自己的解释器扫 70 KB"
的价格；能做的优化（比如让宿主一次多给几个字节、库里按块找 CRLF）都还没做，记在这，别把 9.2 秒读成
门在偷工。

### 7.1 v0.40 在这个服务器上抓到的六个（原文保留，其中三条本轮挪了家）

1. **`bytes()` 和实现说的不一样**。定义写「每个字符取其码，<=255 就是一个字节，更大的拆成 UTF-8」，
   实现原先一律 UTF-8 编码，于是 `bytes("ä")` 定义是 1 个字节、实现是 2 个。这是表面探针测不出来的
   （它只查"定义里有没有这句话"），补的是一个活样本：`print(str(len(bytes("\xe4"))))` → `1`。
2. **POST 回声是乱码**。`reply` 走 `body.encode("utf-8")`，而 `request` 是一字节一字符的 latin-1 串 ——
   两条编码路，正好违反本轮自己那条原则。合并成共用 `_wire()` 之后回声才是字节透明的。
   （v0.41 之后这条更硬：编码只剩宿主 `send` 一条路，库里连"另一种编码"的写法都没有。）
3. **门曾经卡 5 秒**。客户端只发 LF 结尾的请求时，服务器在等更多首部字节，探针在等响应，两边都不肯先走。
   根因就是"行分隔只认 CRLF"这一条没配一个"死等多久"的数 —— 加了 `IDLE_SEC = 10` 直接断连，探针改成
   半关闭（`shutdown(SHUT_WR)`）。**v0.41 这个数搬进了宿主**（定义里那句"10 秒没动静回空串"），
   库只认"空串 = 断"，两边职责一清二楚，台账文本一字没变。
4. **实现说了、定义没说**。实现里 `sock.bind(("0.0.0.0", port))`、`Ctrl-C` 直接退，两句都是真行为，定义里
   一个字都没有 —— 按 §4 的纪律，实现做的每件事都得能在定义里找到原话。补进去之后预算当场顶到 100.0%；
   v0.41 把协议撤出定义时，这两句留在「宿主」一节，额度才退回来。
5. **破坏测试会假装成功**（§6 里 Z7/Z6 那段），起因就是给门加了这份新例子。
6. **「不引用仓库别处」这句独立性，当时还只是文档里手跑的一条 grep**：写 §1 的时候顺手在实现的注释里指了一句
   仓库别处的目录名 —— 那句话让「读这一页就会用」当场不成立，而本地、CI、文档里那句 grep 谁都没红（模式恰好
   不包含那个目录名）。引用已删，检查本身则进了门的第 1 段 + Z11；教训是**判据不能停在文档里**（§6 末段）。


## 8. 这门语言不解决什么

说清楚边界，免得下一篇又写成"顺手解决了工程问题"：

- `drop` 是**计算语言**：写程序、算东西、打印；问外面要东西只有一个 `host`。HTTP 不是它的一部分，
  是它写出的一份库。它不登记承诺、不认识断言编号、不引用变异表 —— 也就是说 v0.38 想解决的
  「需求↔证据失联」它一条都没解决，那是 `lang/` 那条路的事（尚未裁决）。
- 没有赋值 → 没有可变状态。循环只有尾递归一种，**转**不限层数（实测 800 万次），**往里缩**由 E13 限在
  200 层。这是设计取舍，不是疏忽；代价是每个"扫一遍表"都得手写一个带 acc 的具名函数，而这一轮又添了一条：
  **尾位是浅的**（§7 第 2 条），写库的人必须按那一个形状写，否则 201 圈就红。
- 那个 HTTP **库**是最小的，不吹：单线程顺序 accept（一次只服务一条连接）、HTTP/1.1 但只回四个头、
  没有 TLS、没有 chunked、没有路由表、状态原因短语是库里一张表、程序报错直接停。它证明的是"这门语言
  写得出真网络程序"，不是"可以拿去上线"。还有一条更要紧的边界：**它不能上线也不是因为库薄，是因为
  `host` 只有七个命令** —— 没有文件、没有环境变量、没有子进程，所以这门语言此刻写不出任何需要落盘的服务器。
- 参考实现 1,155 行 Python，不追求性能、不产生字节码、**没有标准库**；除了那 8 个内置，什么都没有。
  "没有标准库"这轮有了具体的形状：`lib/http.dr` 是靠命令行顺序拼进去的一份文件，不是 `import` 出来的
  模块 —— 也就是说这门语言现在只有"这一份库"，多一份库就多一个命令行上的文件，没有别的机制。
- 错误码穷举意味着「没有第 15 种」是能测的（`--self-check` 双向比），但穷举的是**这个实现**会吐的码，
  不是所有可能的错误；比如 OOM、磁盘满仍然归宿主，定义里明写了「宿主栈崩不算实现的一部分」。
  连接被断、超限、超时**故意不占码** —— 它们不是程序的错，给它一个 E 码就是多造一个"看起来像 bug"的出口；
  这轮把这条纪律搬了家：现在"10 秒没动静"是宿主给库的一个**空串**，超 64 KiB 是**库**决定断连，两边都不报错。

## 9. 一句话结论

`lang/` 是不是语言，判据是它能不能离开仓库里那五份表 —— 不能。
`drop/` 是不是语言，判据是能不能离开 `drop/` 自己 —— 现在 0 处外部引用、五段门 + 十四条破坏全绿、
定义 1,498 token 在 1,500 之内、读这一页就能起一个真 HTTP 服务器。v0.41 用户那句纠正落地了：**这门
语言现在写得出 HTTP，但不认识 HTTP** —— 协议词汇在定义和实现里 0 处，全在 173 行库代码里，而那条界线
有 Z12/Z13 两条破坏守着，不再是我文档里的一句话。

还欠的三笔，别混着说：新读者的第三次读数没跑（P0），上一轮那 4 份读者程序是作者改写的（不是"读者一次写对"
的证据），本轮新欠一笔 —— **库的 70 KB 扫描 4.6 秒**那个数说明"用自己的解释器写协议"是有价格的，
价格没还（§7 末）。**那一轮的猜中率才是这门语言的分数。**
