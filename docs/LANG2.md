# Droplet 登记语言（`.dpt`）—— 主张、边界、生死判据

这一页回答一个很小的问题：**把"需求 ↔ 判据"的认领关系做成一门语言，比五份 TAB 表好在哪。**
它不是一份路线图，是一份可失败的主张：下面每一条都要么有门守着，要么写着"未测量"。

与 `docs/SPEC.md` 的分工：SPEC 讲的是 C 超集与验收面（blobd 这道题）；这一页讲的是**登记介质本身**。
两者互不取代：`req/` 五份表仍然是**当前生效的题面**（`freeze.sh` 钉的就是它们），
`lang/` 是并行验证物 —— 它没有进冻结清单，所以本轮没有换题，
`FROZEN` 仍是 12 项，变异覆盖分、断言数、样例数一个都没动。

## 1. 主张（以及它为什么不等于"再造一门语言"）

v0.1 造过一门语言：自己的词法、语法、类型检查、代码生成，`code/lang/` 54 个文件 11,813 行 Go，
2026-11-01 在 `2a882c9` 里删掉（109 files，−16,915/+415），理由是「对照实验没有赢，
且它的旗舰服务违反了自己声明的不变量」。那一门语言买的是**语义控制权**，代价是自己背上不变量。

这一门买的东西完全不同，只有三样：

| 概念 | 在表格里是什么 | 在语言里是什么 |
| --- | --- | --- |
| 认领 | `REQ.tsv` 的"断言"列 | `wire` —— 引用不存在 = 编译失败 |
| 署名 | `TRANS.tsv` 的第 6 列 | `evidence S21` —— 说的变异打不中本条款 = 编译失败 |
| 状态 | `REQ.tsv` 的"类型"列 | `status regress\|new\|gap` —— 非法值 = 编译失败 |

现有语言（Eiffel/Racket/SPARK/Dafny 的契约，TypeSpec/Smithy 的 API 形状，Schemathesis 这类
"从 schema 长测试"）验的都是**程序**。这一门验的是**程序与需求之间的关系**，
而且这个关系本身进冻结面。这条缝在盘点时是唯一还空着的格子。

## 2. 三条设计纪律（每条都是被上一轮的失败逼出来的）

**一、定义与检查器是同一份口径，且互相对账。**
`lang/droplet.dpt` 里的错误码表列出会被抓的 20 种错，`dpt-check.py` 的 `CODES` 列出真的会吐的码，
`--self-check` 双向比对：定义多一条 = 文档在骗读它的人；实现多一条 = 有没写进定义的失败模式。
这条纪律的直接来源是上一门语言的死因 —— 规格与机制各写一遍，早晚不一致。

**二、优化的不是语法面，是错误面。**
人的错误成本在读文档那一刻，AI 的错误成本在每次编辑后重跑回路那一刻，而且它每次只看第一条诊断。
所以这门语言允许自己"构造少、报错长"：`E10` 的诊断会把目标实际证明的断言集和条款写的断言集
同时打出来（"目标由 #5 证明，条款写的是 #2 —— 一边改了另一边没改"）。
20 条码每条都有活性样本（`--self-test`，36 个样本逐个打中），码表不是装饰。

**三、扩展点封死。**
任何"注册新构造"的能力都会让"完整定义"变成"定义 + 本项目里的扩展"，
于是"读一遍就会用"这个前提当场失效。所以语法封闭、语义封闭，开放性只在数据层：
`src/promise/choice/hole` 想加多少行都行，关键字一个不加。
这条是人类语言设计会主动反对、AI 受众会主动要求的差异 —— 记住它，它是这个项目的真结论。

**语法零新增概念**是上面三条能成立的前提：`service/promise/choice/hole` 的形状
全部借自模型写过很多遍的东西（接口块、测试用例、配置项），所以它同时"新"和"在分布内"。
它不生成机器码、不做类型推导、不接管宿主语义 —— 语义仍然归 C 编译器和验收表。

## 3. 门（`sh code/sup/lang-check.sh`，已进 `check.sh` 第 7 项）

| 段 | 命令 | 红的意思 |
| --- | --- | --- |
| 1 | `dpt-check.py --self-check` | 定义与实现对账不齐 —— 有一方在说谎 |
| 2 | `dpt-check.py --self-test` | 某条错误码没有样本打得中 —— 码表是装饰 |
| 3 | `dpt-check.py lang/blobd.dpt --against req/`<br>`dpt-check.py lang/blobd.dpt` | 换介质会丢东西；或登记件引用了不存在的判据/有孤儿 |
| 4 | `lang-budget.sh` | 完整定义膨胀过线 —— "读一遍就会用"的成立条件没了 |

破坏测试 #21–#23 验这四段真的会红：定义里凭空加一条码（#21）、把定义加胖过预算（#22）、
擦掉一条反例的署名（#23）。

## 4. 实测（2026-11-06，v0.38）

| 项 | 数 |
| --- | --- |
| 完整定义 | `lang/droplet.dpt` 4,309 B / **1,321 token**（估算）/ 66 行，预算 1,500（占 88.1%）|
| 实验当时的定义 | 3,751 B / **1,138 token** / 62 行 —— 修掉 §5.1 那五处缺陷后涨到 1,321 |
| 错误码 | 定义 20 条 = 实现 20 条；**36 个样本逐个打中 20 条码**，基准样本干净 |
| 等价性 | 一份 `.dpt` 承载 **19 条承诺 / 16 句原文 / 4 处歧义 / 9 个缺口**，与 `req/` 逐栏一致 |
| 交叉验证 | 同一份登记件用工程清单独立判：断言 30 / 目标 18 / 样例 19 / 变异 25，全绿 |
| 一致的历史欠账 | 两边都指出 `S01,S07` 没被任何条款署成反例（TSV 侧是提示，语言侧也是提示 —— 不是错） |
| 介质成本 | 写一份登记要读的：语言 **1,138 token**（实验当时，一个文件）vs 表格口径 **2,384 token**（README §1–§3 + 四份表头）= **47.7%**。修订后涨到 1,321，仍是 55% |
| 未动的东西 | `FROZEN` 仍 12 项、断言 30、样例 19、变异 25、覆盖 30/30、floor 30、`check.sh` 快档 7 项绿 |

`lang/blobd.dpt` 是 `dpt-check.py --emit req/` **机械转写**出来的，不是手写样本 ——
它证明的是"这门语言表达得下一模一样的主张"，不证明"它更好写"。后者要靠下面的三臂实验。

## 5. 三臂实验：只给定义，够不够写对

做法（`lang/ab/`，判卷器 `code/sup/ab-score.py`）：同一份三句话需求 + 同一份小清单
（6 条断言、2 个目标、2 个样例、4 个变异，其中一半与这三句无关），7 个**全新上下文**的会话各写一份登记件。
两个臂用**同一个判卷器**：`.dpt` 走解析器，TSV 走列读取，两边归到同一结构后跑同一组规则。

| 臂 | 给了什么 | n | 结构合法 | 格式 |
| --- | --- | --- | --- | --- |
| 1 | 只有 `lang/droplet.dpt`（62 行定义，零例子） | 3 | **3 / 3** | 解析器全收 |
| 2 | 定义 + 一份别人项目里验收通过的登记件 | 1 | 1 / 1 | 同上 |
| 3 | 表格口径（README §1–§3 + 四份表头，2,384 token） | 3 | **2 / 3** | 0 行列数错 |

**这张表不能用来宣布胜利**：n=3 vs n=3，1 条之差是随机波动（而且臂 3 那条 `E17` 是"缺口没在反例里点名"，
两臂同规则）。真正的产出在下面两张清单上。

### 5.1 只读定义的会话报出来的定义缺陷（按报告次数排）

| # | 缺陷 | 报告 | 处置 |
| --- | --- | --- | --- |
| D1 | 源句用 `S<n>`、变异也用 `S<n>`，同一前缀两套所指 | **7 / 7**（含表格臂 3/3，是介质共有的坑） | 已修：变异改 `M<n>`，写 `S` 直接 `E01` |
| D2 | 定义 L7 说"每个变异都要被认领"，实现只把断言/样例/目标当孤儿 | 4 / 7 | 已修：措辞与实现对齐；另加"增量登记"口径（`--partial`） |
| D3 | `hole` 语法写了 `open`，但 `E16` 把它判红 —— "真没闭"没有诚实的表达位 | 3 / 4（只读定义的臂） | 已修措辞：`open` 是合法写法，**按设计**挡住提交（与表格里"未闭 = 红"同口径） |
| D4 | 字符串没写转义规则，导致**断言的精确 body 字面量写不进去** | 4 / 4 | 已修：定义里写明 `\"`、`\\`、`\n`，其余 `E01` |
| D5 | 没有基线时 `status new` 触发 `E19`，于是只能全写 `regress` | 3 / 4 | 已修：`E19` 只在 `--strict` 下触发，先红后绿仍由登记核对那侧负责 |
| D6 | `choice` 只能锚 `src`，**语言自身的歧义没有登记位** | 2 / 4 | 未修，记在下面 §7 |
| D7 | 排版、服务名、字段顺序、文件末尾均未规定 | 2 / 4 | 已修：定义写明排版不参与语义 |

D4 是这批里最贵的一个：**精确 body 正是 v0.36 那条 `#27` 能抓住"值被写成数字数组"的原因**，
转义规则没写出来，四个会话里有四个只能把字面量改写成中文描述 —— 检查力度当场就掉了。

### 5.2 两个更不好听的发现

1. **为凑绿而编内容，两臂都发生了。**语言臂 4 个会话里有 3 个造出与三句原文无关的承诺（借 `from S1`
   挂靠），只为把清单里 `#1`–`#4`、`S3`/`S4` 的孤儿账平掉；表格臂也有人做了同样的事（另两人拒绝并写明冲突）。
   根因不在介质，在**实验的清单里混进了别的接口的判据**，而"这份登记只覆盖三句话"这个状态在两种介质里都表达不了。
   已加 `--partial`，但它是命令行开关，不是语法 —— 真正的答案是语言里要有一个"部分登记"的声明。
2. **判卷器自己有 bug，而且第一轮数字是错的。**第一版 `E09` 把 `gap` 条款也要求有判据（与 L2 矛盾），
   首轮评分于是两臂各多算 2 条失败；修完才是上面这张表。更该记住的是：**`--self-check` 只对了码表，
   没对语义** —— 定义与实现说"同一个规则"这件事，目前仍靠人读。这是五道门里第一次在**自己这一层**
   看到"文档与机制各写一遍，早晚不一致"。

### 5.3 实验自身的缺陷（跟着数字一起放）

模型在环由同一模型家族的隔离会话充当，不是独立评测；n = 3/1/3；夹具里 TASK 散文与
`inventory.json` 对变异 `S3` 的命中目标写矛盾（7 个会话里 5 个发现并按 JSON 处理）；
臂 2 给的样本是节选、缺 `service` 外层，被自己的解析器判了 `E03`。

## 6. 生死判据（任一不成立就删掉这门语言，退回 Babel 插件路线）

| 判据 | 门槛 | 现状 |
| --- | --- | --- |
| 定义能装进一次阅读 | ≤ 1,500 token | 1,138，绿 |
| 表达力不缩水 | 与 `req/` 逐栏等价 | 19/16/4/9 全对上，绿 |
| 检查不缩水 | 四段门 + 破坏 #21–#23 全绿 | 绿 |
| **只读定义就能写对** | 臂 1 的结构合法率不低于臂 3 | 3/3 vs 2/3 —— 不劣，但 n 太小，不构成优势 |
| **定义能被读透** | 只读定义的会话能指出定义没说清的地方 | 4/4 指出，共 7 类，5 类已修 —— 这条比上一重要 |
| **省下的 token 是真的** | 介质 1,138 vs 2,384 | 已测（47.7%） |
| 规模红线 | 语言侧总代码 ≤ 3,000 行 | `dpt-check.py` ~560 行，绿 |

本轮判定：**留着，但降级为"实验性介质"** —— `req/` 仍是生效题面，`lang/` 不进冻结。
理由不是臂 1 赢了（它没赢），是省下的 55% 阅读面是真的、D1–D5 只有靠语言才修得这么快、
而 §5.2 那两个发现（编内容凑绿、码表对账抓不到语义漂移）说明它离"换掉表格"还差得远。
下一轮如果要做真替换，第一件事是 §7 的 D6 和"部分登记"进语法。

## 7. 边界（别把它说大）

- 这门语言管**机制层**：怎么声明、什么合法、错了得到哪句诊断。它不管**意图层**：
  该提什么需求、空白要不要约束、"空目录"和"读不到目录"是不是一回事 ——
  那些仍然是 `choice`/`hole` 里由人写的字，语言只保证你**不能不写**。
- 语言侧的等价性证明只覆盖"blobd 这一道题的登记件"。换一道题、换一个宿主，
  `dpt-check.py` 靠 `--inventory` 拿外部清单工作（本轮三臂实验就是这么隔离的），
  但**没有**在第二个真实项目上跑过完整的五道门。
- `D6` 未修：**语言自身的歧义没有登记位**。`choice` 只能锚定源句，
  所以"这两种读法哪个算合规"这种元层问题只能塞进某条 promise 的 `hole` 文本里；
- 三臂实验的模型在环由同一模型家族的隔离会话充当，不是独立评测（§5.3）。
