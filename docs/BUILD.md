# BUILD.md —— 从 0 打造一门语言：路线、判据、量尺

> 这一页只服务一个目标，用户 2026-11-12 的原话：**「我最终目的就是学习一门新语言是如何从 0 开始打造的过程的」**，
> 并给了四条需求：API 极简 / AI 读完文档源码就会用 / 编译成什么必须想清 / 运行时 CPU·GPU·内存越小越好。
>
> 它不是历史（历史在 DROP.md），也不是待办清单（那是 NEXT.md）。它是**一条每一段都能判真假的路**。
> 写这页的规矩：出现的每个数字都是这台沙箱里刚量出来的，命令附在旁边，谁跑谁能对上；
> **没量过的数字不许当判据**，量出来不好看也不许改措辞。
>
> 页种：新开的一页。老页（DROP.md / SPEC.md / NEXT.md…）不改写，只加注解 —— 沿用 v0.42 定的规矩。

## 0. 四条需求先翻译成可判的形式

「极简」「越小越好」这种话不能直接开工，必须先变成一条命令能红能绿的东西。

| 需求 | 可判的形式（判据长什么样） | 今天在哪 | 谁来判 |
| --- | --- | --- | --- |
| API 极简 | 宿主缝只有 `host(命令,参数)`，命令数 = 定义里那张表，双向比（多一个少一个都红） | **已有**：7 个命令，`check.sh` 第 [2/5] 段双向比 | `drop/check.sh` |
| AI 读完就会用 | 只喂定义、不喂源码，AI 交回的程序/宿主必须过同一把秤（§5 三道验收） | **未验**：v0.38 那次是冷读（人），且交回 25 条「靠猜」 | 阶段⑥ → §5 |
| 编译成什么想清 | 目标定了之后，定义必须写得出「产物是什么」这一句，且新宿主靠它就能对齐 | **未定**：现在是树遍历，产物是数据不是指令 | 阶段⑦⑧ + §4 |
| 运行时越小越好 | 一条命令量出 RSS / 启动耗时 / 磁盘，钉死预算后只准降不准升（§3） | **只有量尺，没有预算** | `tools/footprint.py` |

两句结论先放在这里，因为它们是后面所有判断的地基：
**内存那一头，13.9 MB / 26.5 MB 里几乎全是宿主运行时的地板，不是这门语言的开销**（§1 读法 1）——
所以「运行时越小越好」指向的是**换目标**（§4）；
**CPU 那一头，每步 ≈2.3 µs 的负担确实来自「树遍历」这个形式本身**（§1 读法 3，两份宿主几乎一样）——
所以换目标确实能省 CPU，但省不到定义里那两条 O(n²) 的语义上去。

## 1. 基线（今天的实测）

复现：`cd drop` 后照抄下面命令；`--reps 5` = 跑五遍，耗时取最快、RSS 取最大（取最大是有意的，见 §3）。

| 被测 | 峰值 RSS | 最快 | 命令 |
| --- | --- | --- | --- |
| py 宿主 · 空跑（只打 usage，rc=2） | 13.7 MB | 55.2 ms | `python3 ../tools/footprint.py --name py:idle --reps 5 -- python3 hosts/python/interpreter.py` |
| py 宿主 · `examples/fact.dr` | 13.9 MB | 56.7 ms | `… -- python3 hosts/python/interpreter.py examples/fact.dr` |
| py 宿主 · `examples/spec.dr` | 14.0 MB | 168.9 ms | `… -- python3 hosts/python/interpreter.py examples/spec.dr` |
| 参照 · `python3 -c pass` | 8.5 MB | 26.8 ms | 上面任何一条加 `--python-floor` |
| cs 宿主 · 空跑（rc=1） | 24.8 MB | 62.3 ms | `… -- dotnet hosts/csharp/bin/Release/net8.0/droplet.dll` |
| cs 宿主 · `examples/fact.dr` | 26.5 MB | 77.4 ms | `… -- dotnet …/droplet.dll examples/fact.dr` |
| cs 宿主 · `examples/spec.dr` | 45.3 MB | 171.3 ms | 同上 |
| 每步成本（**推算**：跑 `spec.dr` − 宿主空跑，再除以 5 万步） | — | py ≈2.3 µs · cs ≈2.2 µs | 见读法 3 |

重复跑同一批命令的漂移：RSS ±0.1 MB（8.4 与 8.5 都出现过），耗时轻程序 ±0.5 ms、重程序 ±2.5 ms。
上表记的是今天那一遍的数，**别把它当规格**。

另一头（`conform.sh` 第 [4/4] 段的口径，只报数）：**一个进程连着跑完 11 份语料** —— python3 168 ms / dotnet 175 ms，
摊到每份 15.2 / 15.9 ms。**这个 168 和上表 `spec.dr` 单跑的 168.9 只是撞数，口径完全不同**：
上表是「一次进程 · 一份程序」，这段是「一次进程 · 十一份程序」。两个数都记着，但谁也不许拿去解释另一个。

**读法（三条，都是这页的立论）：**

1. **减出「这门语言自己要的」**：py 跑 `fact.dr` 比空跑多 **0.2 MB / 1.5 ms**；cs 多 **1.7 MB / 15 ms**。
   也就是说几十行的程序、1,192 行的解释器，自己要的东西在这个量级。开销在宿主运行时身上。
2. **地板是谁给的**：选「依附宿主」这条路，`python3 -c pass` 的 8.5 MB / 27 ms 就是白送且砍不掉的起点。
   cs 那边参照必须用「宿主空跑」而不是 `dotnet --version` —— 后者量出 **44.6 MB / 141 ms**，那是 dotnet muxer
   在干别的事（找 SDK、读 XML 文档），拿它当参照会把 cs 宿主的开销算成负的。**这就是「参照命令要选对」的活例。**
3. **两种「慢」必须先分清，再决定换不换目标**（这一条是本页最值钱的一课）：
   - `spec.dr` 那 169 ms 里装的是**定义第 1 行那个 `count(50000, 0)`** —— `fn count(n, acc) { if(n <= 0, acc, count(n - 1, acc + 1)) }`，
     五万次尾递归、纯整数加法，**没有一处表操作**。减掉宿主空跑（55.2 / 62.3 ms）剩下 **≈114 ms / ≈109 ms**，
     摊到每步 **≈2.3 µs（py）/ ≈2.2 µs（cs）**。这是**推算**，量的是两份程序的差 —— 但它指向的正是
     字节码 VM 能吃掉的那一类开销：每步的解释负担。两份宿主**每步几乎一样**这件事本身说明差距不在
     「python 慢、c# 快」，在「树遍历」这个形式上。
   - 另一份 `hosts/csharp/probe/e13tail.dr`（10 万层尾调用 + 10 万长切片）两边 **84 s / 124 s**，
     慢的是**定义里的 `acc + [n]` 与 `xs[1:]` 都是 O(n²)** —— 换 VM 不会快，除非改语义，
     **那就不叫换目标，叫换语言**。
   所以阶段⑦的正确提问不是「哪个目标更快」，而是「我要省的是**每步 µs**，还是**语义本身**」。

**装什么才能跑（这一栏才是第四条需求的正面回答）：**

| 东西 | 大小 |
| --- | --- |
| CPython 解释器本体 `/usr/bin/python3.12` | 7.9 MB |
| + 标准库 `/usr/lib/python3.12`（不含 `__pycache__`） | 42 MB |
| + 扩展模块 `lib-dynload` | 3.3 MB |
| .NET 8 共享框架 `Microsoft.NETCore.App/8.0.33` | 67 MB |
| drop 的 C# 产物（dll + apphost + 两个 json + pdb） | 133 KB（去掉 pdb 110 KB） |
| `drop/` 全部源码（定义 + 库 + 两份宿主 + 两道门，不含 `bin/obj/.git`） | 0.21 MB / 247 个文件 |
| `libc.so.6`（任何 Linux 上都在） | 2.2 MB |

今天的及格线：**为了跑一个 27 行的 HTTP 服务器，要么背上 42 MB，要么背上 67 MB（这两栏是磁盘上装的东西，不是进程 RSS）。** 两条都不及格。
阶段⑧的靶子因此写得非常具体：**一个 C 写的小 VM，产物几十 KB，除了 libc 什么都不背**，
用 §3 的量尺证明它比 8.5 MB 那个地板更低，才算赢 —— 而不是跟 13.9 MB 打平就叫成功。
CPU 那一头再补一条同样具体的：**每步要明显低于今天的 ≈2.2 µs**，否则换了目标只是换个宿主，白付 §4 那笔定义的钱。

## 2. 十阶段路线

顺序不是审美，是依赖：④不定就没法做⑥，⑥不过就没资格做⑦，⑦不定就没法做⑧。
每段四件事：**问题 / 产物 / 判据（可跑）/ 最易自欺之处**。「现状」指的是这个仓库今天已经走到哪。

### ① 词法
- **问题**：字符流到 token 流，边界在哪、注释算什么、串里能不能有换行。
- **产物**：一个 scanner + 一份「哪些字符能出现」的穷举。
- **判据**：给一批畸形输入（BOM、CRLF、串未闭合、行中断在半个 token），每条都必须在**同一行**报出**同一码**，两份宿主对得上 —— 今天由 `conform.sh` 第 [2/4] 段担着（73 条样本，0 漂）。
- **最易自欺**：把「我的 tokenizer 没崩」当成「词法有定义」。**没崩 ≠ 两份宿主同意**。
- 现状：**已有**，两份各写一遍（`hosts/python/interpreter.py`、`hosts/csharp/interpreter.cs`）。

### ② 语法（递归下降）+ 排版规则
- **问题**：语法本身很小，真正咬人的是「换行/缩进怎么切句」这条排版规则。
- **产物**：AST + 一份排版规则的**正例与反例各一叠**。
- **判据**：排版反例（`tests/layout/`，今天 8 条）每一条都必须报错，正例（`layout_ok_*.dr`，2 条）必须逐字节等于 `*.out`。
- **最易自欺**：用「能跑通的例子越写越多」代替「不能跑通的例子也越写越多」。反例才是语法的地基。
- 现状：**已有**，正例 2 条 / 反例 8 条。

### ③ 树遍历跑通语料
- **问题**：语义（作用域、闭包、表、尾调用）在 AST 上直接落地。
- **产物**：`ev(node, env)` 一个函数 + 语料。
- **判据**：`examples/*.dr`、`tests/*.dr` 逐字节等于 `*.out`（`check.sh` 第 [1/5] 段）。
- **最易自欺**：树遍历「什么都能跑」，所以什么错都像是实现 bug 而不是语义没定 —— 这一步攒下的模糊，全部在④⑥爆出来。
- 现状：**已有**。

### ④ 错误码穷举与落点
- **问题**：每条码**什么时候**报、报在**哪一行**、谁**先**报。
- **产物**：定义里的错误码表 + 每条一个**真能触发它**的样本。
- **判据**：`check.sh` 第 [2/5] 段 —— 码表双向比，每条都有样本；`conform.sh` 比 rc / stdout / 「第 N 行 Ex」。
- **最易自欺**：**「两条路都合理」的分支没钉死**，于是两份宿主各猜一边，测试还都绿。这就是本项目说的「巧合一致」，
  今天已查明 **5 处**（CRLF 与末行换行、顶层同行两句、跨行错的行号落点、`host` 少参先 E2 还是 E14、注释占不占行号）。
- 现状：**已有**，但已知欠账 5 处 —— 定价见 §4 末。

### ⑤ 定义压到一页 + 机器可读的 API 表
- **问题**：一页纸装得下的才是语言，装不下的是文档。同时，「API 极简」需要一个能被程序读的表，而不是散文。
- **产物**：`spec.txt`（唯一规范来源）+ 一份 API 表（宿主命令 / 参数 / 返回 / 错的码，一行一条）。
- **判据**：token 预算（**1,497 / 1,500，余 3**；字节 9,823 / 10,240，余 417）+ 定义可执行（第 [4/5] 段：从 `spec.txt` 抽出的例子必须与 `examples/spec.dr` 逐字相同）。
- **最易自欺**：**用文档买功能**。定义里没写、README 里写了，等于没写。
- 现状：定义**已有**（135 行 / 1,497 token，一页）；**API 表还没有** —— 这是①–⑥里唯一真正未完成的一段，也是最小的一块改动，建议第一个动。
  表形如（示意，不是产物）：`bind  fd,port  -> fd | E2,E11`。

### ⑥ 冷读验收（人 or AI 只读定义）
- **问题**：定义是否**完备**，只有没看过实现的人（或模型）能测。
- **产物**：冷读记录 —— 写出几个能跑的程序、交回几条「靠猜」。
- **判据**：**猜的次数 = 0**。这条本项目真量过一次：v0.38 冷读写出 3 份能跑的程序，同时交回 **25 条「靠猜」**，补完这 25 条才到 1,100 token 上下。
- **最易自欺**：让写过实现的人做冷读；或者把「跑通了」当成「没猜」——跑通可能只是猜对了，**必须让他把猜的地方列出来**。
- 现状：人做过；**AI 版没做过**，见 §5 的 A1。

### ⑦ 指令集设计
- **问题**：要编译成什么。这是第四条需求和第三条需求的交汇处，选项与代价见 §4。
- **产物**：指令表（每条：名字 / 操作数宽度 / 对栈的效果 / 错的码）+ **定义里那句「程序先译成字节码」**。
- **判据**：一张表 + 一段能编出这字节的程序；指令集必须**穷举**（表外操作码是错误），否则「换宿主」就是空话。
- **最易自欺**：指令集越设计越大 —— 每多一条指令，就多一条要在两份宿主上对账的东西。判据应当包含「指令条数上限」，且这个上限要**先于**写指令定下（先定后写才叫预算）。
- 现状：**未开始**。前置：⑤的 API 表 + ④那 5 处定价。

### ⑧ 小 VM（C）+ footprint 量尺进 CI
- **问题**：把⑦那张表变成能跑的几十 KB 的东西，同时证明它真的省。
- **产物**：`vm.c` + 一份字节码 + `tools/footprint.py` 的预算行进 CI。
- **判据**：同一把秤（`conform.sh` 第 [1/4]、[2/4] 段的语料与报错样本）对新 VM 跑出**同一张表**；
  且 `footprint --budget-mb/--budget-ms` 在钉下的预算内为绿。工具链已确认可用：沙箱里 `cc` 是 gcc 13.4。
- **最易自欺**：**只报「小了多少」不报「语义漂了多少」**。省 30 MB 但错了两条报错落点，是输不是赢 —— 所以这一步的判据必须**两把秤一起读**，任一红就整段红。
- 现状：量尺已有（§3），预算未钉，VM 未开始。

### ⑨ 同一份字节码换宿主
- **问题**：这才是「编译成什么」的回报 —— 字节码是产物，宿主只是缝。
- **判据**：**同一份 .dcb 文件**在 VM 上、在嵌了 VM 的 py 宿主里、在嵌了 VM 的 cs 宿主里，stdout/stderr/rc 逐字节相同（拿 `conform.sh` 测，前提是先做 §5 记下的那个「被测命令可换」改动）。
- **最易自欺**：三份各写一遍「差不多的」编解码，然后靠测试兜住。判据必须包含「编解码只有一份源码」。
- 现状：**未开始**。

### ⑩ WASM 后端（可选）
- **判据**：同一份字节码在浏览器里跑出同样的 88 行实录。
- **最易自欺**：把「能编译到 WASM」当成「运行时小」—— wasm 里跑 C 的 VM 依旧要背上堆和 syscall 缝，**量完再说**。
- 现状：**未开始**，且明确是可选的。

**关于「GPU」**：四条需求里那句「GPU 越小越好」在这条路上没有对应物 —— 这门语言没有任何一步需要 GPU，
`host` 那 7 个命令里也没有。**建议把这条需求改写成「依赖越少越好」**（磁盘 / 装的东西 / 进程数 / 起进程到第一行输出的延迟），
那样它就能判了；上面那张「装什么才能跑」表就是它的量尺。**这不是抬杠，是因为留着 GPU 这个词，就没有任何一步能被它判真假。**

## 3. 量尺：`tools/footprint.py`（现成能跑）

一件工具，三件事：**峰值 RSS、启动到退出的耗时、磁盘**。它不改被测程序，只 fork/exec 然后 `wait4` 拿子进程的 rusage。

```sh
cd drop
# 只报数（默认不判）：跑 5 遍，耗时取最快、RSS 取最大，并给一条参照
python3 ../tools/footprint.py --name py-host --reps 5 --python-floor \
    -- python3 hosts/python/interpreter.py examples/fact.dr
#   py-host    峰值 RSS    13.9 MB / 最快     56.6 ms / rc=0
#   参照 8.5 MB / 26.6 ms（rc=0）← /usr/bin/python3 -c pass；被测比它多要 5.4 MB
#   footprint: 只报数 —— 没给预算就不判（没量过的数字不许当判据）

# 判（给预算才判，红必须说清是哪一条）
python3 ../tools/footprint.py --name py-host --reps 5 --budget-mb 10 -- python3 hosts/python/interpreter.py examples/fact.dr
#   footprint: 红 —— RSS 13.9 MB > 预算 10.0 MB          （退出码 1）

# 磁盘（默认跳过 bin/ obj/ __pycache__/ .git/）
python3 ../tools/footprint.py --name disk --disk . --disk ../docs -- python3 -c pass
#   磁盘 .            0.21 MB / 247 个文件（排除 /bin/,/obj/,__pycache__,/.git/）
#   磁盘 ../docs      0.23 MB / 7 个文件
```

三条纪律，全是这页的规矩，不是这个脚本的花絮：

1. **不给预算就不判**，最后一行明写「只报数」。防止把「跑通了」读成「达标了」。
2. **红必须归因**：先看退出码，再看预算；被测命令起不来时后面都不配谈。
   `--expect-rc` 用来钉「这条命令本该返回几」—— 两份宿主**空跑**的返回码就不一样（py 是 2、cs 是 1），
   拿默认的 0 去量它们，红会正确地报在退出码上，而不是假装量出了 13.7 MB。多遍码不一致时打印实际码，不糊成一句「失败了」。
3. **差值才算数**：`--python-floor` / `--floor-cmd` 是给你剥地板用的。参照选错会得出荒谬结论（见 §1 读法 2）。

**怎么钉预算**（第四条需求现在还没有预算，只有尺）：
先量 5 遍 → 把今天的数原样写下 → **预算 = 今天的数**，不是愿望 → 从那天起只准降不准升 →
真需要升就是**放宽**，必须在这一页记一行：谁、为什么、从多少到多少。
这套记账法是从 `check.sh` 里那个 1,500 抄来的（它的完整历史：497 → 1,100 → 1,750 → 退回 1,500，
**抬的那一次和退的那一次都写在门里的注释上**，见 `check.sh` 第 19–22 行）。

## 4. 编译成什么：必须先算的账

「编译成什么必须想清」这件事，在 drop 这里有一笔硬账，因为**定义只有一页、只剩 3 token**。

| 选项 | 产物 | 运行时地板 | 语义代价（要往定义里写什么） | 适合这页目标吗 |

- **新页 + 新预算**（=换对象）：`drop/spec.txt` 原样冻结做参照与量尺，编译目标这条线另起一份定义、另开一个预算数。
  **代价是从此有两份定义**，得写明谁是权威。
- **抬老页预算**（=放宽）：`1,500 → 1,750` 这类动作，按规矩**必须当次报告成「放宽」**，不许写成「增长」，

本页**建议第一个**（换对象），理由是学习目标：一页纸的语言 + 一份带字节码的语言，是两个不同的练习对象，
混在一页预算里会同时失去两边的判据。**但这是待你裁决的（§7），这页不能替你定。**

**顺带把 ④ 那 5 处「巧合一致」的价格更新一下。** 已有的实测样本三个：`NEXT.md` P0c 量过两句 ——
「跨行的错报在断掉之前那一个记号所在的行」**6**、「行号按物理行数，注释也占行」**4**；

今天的余量是 **3**。所以这条待办的性质变了：不再是「要不要写清楚」，而是
**「换 VM 之前必须先把地板焊平」** —— 因为那 5 处正是换 VM 时最先漂的地方

顺序因此应当是 **先焊平 5 处，再动指令集**；两笔账合起来 **≈230 token**，一页纸的预算怎么都装不下 —— 这是 §7 第 2 条要裁决的核心。

## 5. 「AI 读完就会用」的三道硬验收

第四条需求写的是「适合 AI 快速阅读文档与源码后就会用」。**「就会用」不能靠感觉**，下面三条各有一个红。

| 编号 | 唯一输入 | AI 要交回 | 判据 |
| --- | --- | --- | --- |
| **A1 会用** | 只有 `spec.txt`（不给 README、不给文档、不给宿主源码） | 一个 ≥10 行的程序 | 它必须过 `check.sh` 第 [1/5] 段那种逐字节比对（与 `*.out` 对，或人先看是否**无需提问**就能写对） |
| **A2 会实现** | 只有 `spec.txt` + §5 那张 API 表 | 一个新宿主（第三种语言） | `conform.sh` 把被测命令换成它，必须**语料 11/11、报错 0 漂**（实录段跳过：它没有 socket 也算不得红，另记） |
| **A3 会维护** | 只有 `spec.txt` + API 表 + 一份宿主源码 | 一处**本地化**改动（例如把某条错误的中文说明换掉），不许动语义 | 改完：语料仍逐字节、73 条报错样本「第 N 行 Ex」的 **N 和 x 都不许漂**，只有文案漂 |

机械化程度：A2/A3 用的就是 `conform.sh` 那张表 —— 但**今天它把两份宿主写死在里面**，接第三份要先把它改成「被测命令可换」的形状，这是阶段⑤之后第一个小改动，本页如实记在这儿；
A1 还需要一份「只拷 `spec.txt` 进空目录」的输入打包脚本，**那是阶段⑤的第二个产物**。
三条里**任何一条**做不到，第四条需求就只能算「文档写得挺好看」。**当前状态：一条都还没跑过。**
