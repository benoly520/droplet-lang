## 1. 五分钟上手

```sh
sh code/sup/check.sh --full                    # 一条命令一个退出码（14 项）
```

需要：`cc`（C11）、`sh`、`python3`、`git`、`flock`、`curl`。不需要 Go。

## 2. 待办（按优先级）

### P0 · `drop` 第三轮冷读：换一个没读过任何历史的读者

v0.40 只做到「把上一轮读者写的 4 份程序改写成"只有一种写法"的版本跑绿」+「按它交回的 7 条洞逐条落地」+
「自己起真 socket 打服务器」；v0.41 又加了一件同样由作者自己验的事：**用这门语言把 HTTP 库写出来**
（`lib/http.dr` 170 行，另有第二份宿主 `cs/Drop.cs` 1,692 行）。所以 `drop` 的定义写得完不完，到现在仍然没有**读者口径**的独立读数 —— 而且本轮多了一层：
**库好不好用也没有**，写库的就是作者自己。要说公平话：v0.42 那份 C# 宿主**确实是一次独立阅读**（同一间干净房间、
同一个"只许看 spec.txt"的约束，交回 40 处"定义没说了算"），但它读的目标是"怎么写解释器"，不是"怎么用它写程序"
—— 它列出的含糊全是词法/语法边界，一条关于库或惯用法。所以 P0 没被它替掉，只是被它**加了个更窄的兄弟**：
再要一个"只用这份语言写四份程序"的读者读数。要做的是：

1. 开一个全新上下文的读者（上一轮试过：`create_agent` 被「并发子线程上限 25」拒了 —— 要么先回收线程，
   要么把任务拆到下一个会话），**只**给它 `drop/spec.txt`，禁止读 `drop.py`；
2. 让它写 4 份程序（含一份故意写错看报什么码）+ 交回「不得不猜」的清单；
3. **这轮的那一题换成"读定义 + 读库"两档**：(a) 只读 `spec.txt` 写出能应答 `GET` / `POST` 的程序，
   **不许读 `lib/http.dr`** —— 考的是 `host` 那七个命令写完了没有；(b) 允许读库，把程序接到 `http_serve()`
   上 —— 考的是"库的接口能不能只靠读代码学会"。两份都拿 `tests/http_check.py` 的台账对行为。
   (a) 里最容易暴露的是本轮作者自己撞上的那三条（尾位浅、没有赋值、没有 `ord`），读者撞不撞得到才算数；
4. 逐份机械跑：绿/改几次才绿/FAIL 都要写进 `drop/tests/` 或 DROP.md，不许只报"看起来行"；
5. 猜的次数如果比第二轮（25 条→21 闭→7 新洞）还多，就**在 1,500 之内重写定义**：本轮把预算从 1,750
   退回 1,500，现在占 99.9%，加一句必须删一句 —— 这条不是估的，是门（第 3 段）当场会红。

验收线：新增的读者程序进 `drop/tests/`，`sh drop/check.sh` 仍全绿，DROP.md §5 有第三轮的实测数字。

### P0b · 分层的价格还没还（本轮新欠）

那条 70,000 字节首部的用例现在单条 **4.63 秒**（协议在 Python 里时整条台账 0.22 秒，现在整条 4.96 秒），
因为 `find_blank` 是一个字符一次解释调用地在 drop 里走。两个方向都能治，都还没做：

1. **按块扫**：库里一次 `recv` 拿回来的整块先数 `len(buf)` 再决定要不要重扫，而不是每字符一次递归；
2. **让宿主多给一点**：`recv` 现在固定一次 4096 字节，定义里那句「阻塞到至少一个字节」并不禁止"能给多少给多少"。

动第 2 条就是动定义，必须先删一句别的（预算 99.8%）。判据不变：`tests/http.expected` 的线上字节一字不许变，
门时间必须降下来 —— 降不下来就是没治到根因。

### P0c · 预算已经挡住"把含糊写清楚"了 —— 三条路必须选一条（用户裁决）

v0.42 之后秤是绿的，剩下 5 处「两份宿主各猜了一种读法、恰好猜一样」（DROP.md §10.6）：
`
` 算不算行尾、顶层同一行写两句要不要正面允许、**跨行的错报在哪一行**、`host` 少给参数先 E2 还是先 E14、
注释占不占行号。前两条已经能靠推理，后三条推理不出来。

**价格是量出来的，不是感觉：** 写清楚其中两条要 10 个 token（「跨行的错报在断掉之前那一个记号所在的行」6 个、
「行号按物理行数，注释也占行」4 个），而现在能腾出来的只有 3 个（删掉第 125 行那句观察不到的例外）。

| 路 | 做什么 | 代价 |
| --- | --- | --- |
| (a) 抬预算 | 1,500 → 1,510 或更多 | 这是**放宽**，按规矩得当收紧报：必须给"为什么这次可以"，而且 §0 那句「预算 = 读完这一页就会用的成立条件」要重述 |
| (b) 删一句真的换 token | 候选：第 125 行那半句死例外（腾 3）、`str` 与 `print` 对表的两种写法（能不能合成一条？合成会不会让语料变）、七个 `host` 命令里 `peer` 能不能由 `recv` 承担 | 每删一句都要连带改探针与语料，且必须证明"没变难用" —— 这是真活，不是腾字 |
| (c) 不动定义 | 5 处继续记在文档里当已知含糊 | 零成本，但"同一页定义长出第二份宿主"这句话的可信度就靠这 5 处撑着 —— 下一份宿主可能猜不一样，那时它是对的、我们是错的 |

维护者本轮按 (c) 走，**没有偷偷改预算，也没有偷偷加句子**。下一轮要么用户点头走 (a)，
要么老实做 (b) 的一次删换。不许用"补一句定义"的名义把预算当橡皮筋。

## 4. 坑（踩过的）

- **并发拉起的子进程要自己排队**：运行时对每次成功写入并发拉起 `DP_COMMIT_CMD`，
  裸 `git commit` 会抢 `HEAD` 的 ref 锁并静默丢一条提交（CI 上实测挂过 #23）。用 `flock` 串行。
  `flock` 只排开 ref 锁，排不开内容：写入快于提交时两次提交看到同一份文件，先拿到锁的那次提交为空
  （ASan 下稳定 3/4）。验收表因此逐写等提交落地；生产环境开 `DP_COMMIT_DEBOUNCE`，别用 0。
- **端口残留**：上一轮实例没死，新实例 bind 失败但请求照样有响应 —— 测到的不是这份代码。
  `accept-table.sh` 起服务后先 `kill -0` 再断言；手跑前 `pkill -x blobd`（`pkill -f` 会匹配到自己）。
- **脚本搬家要重算 `ROOT`**：`accept-table.sh` 在 `code/webapi/deploy/` 下，`ROOT` 是 `../../..`。
- **破坏测试的“红”必须归因到具体工具**：注入代码少个 `#include` 也会“红”，那是编译错误冒充检查成功。
  每条破坏都断言诊断文本，且必须有一条“本该全绿”的干净参照。
- **表里少一行不会红，实现多一个会红**：`-Wunused-function` 只抓“实现了但没进表”，
  反过来靠 `used but never defined`。两边都要有破坏测试（S1/S2）。
- **`nm -u` 看的是引用，不是源码**：接线检查靠它，所以改名、拆文件都绕不过去 —— 这是有意的。
  接线检查要能看见运行时引用，就必须把运行时也逐 TU 编成 `.o`；一个 `cc` 调用直接出可执行文件，
  符号表里就没有那条引用了。
- **接线对是手写的清单**：`build.sh` 与 `sabotage-sup.sh` 各有一份，搬新决定时要同时加，
  否则容易只绿一边。两处都按“谁的 .o 必须引用哪个符号”写，不按文件名猜。
- **候选比较的“歧义”不是工具坏了**：两份同外延实现在样例上等价时，工具必须报歧义。
  想让它变“唯一”，办法是加样例，不是放宽判定。
- **`--self-check` 只对了码表，没对语义**：v0.38 第一轮的 E09 把 L2 写反了（`gap` 条款也被要求署证据），
  码表照样“绿”，判出来的分数却是错的 —— 三臂实测的第一轮数字因此作废。规格对账不等于实现对账，
  任何当判据用的东西都要有一条“它自己会不会错”的样本。
- **定义里的例子必须机器抽出来跑，否则作者会在自己的定义里写非法程序**：`drop` 第二轮被读者当场抓出
  「spec 举的那行例根本不是这门语言的合法句」。修法不是加一句"请注意"，是加一条门：带 `> ` 的行逐字抽成
  `examples/spec.dr`，与提交版逐字比，再跑一遍比输出（`drop/check.sh` 第 4 段 + 破坏 Z5）。
- **委派有并发上限，实验要能降级**：第三轮冷读开不出新读者（25 线程满）。别把结论挂在"读者会回话"上：
  先用机械复核把能测的测掉，读数欠账显式记成 P0。
- **临时树里跑的检查要显式传 `--root`/`--spec`**：`sabotage-sup.sh` 把 `lang/` 复制到 `/tmp` 再改，
  从脚本自身位置推 `ROOT` 的检查器会指到 `/lang/droplet.dpt`（表现为 `FileNotFoundError`，
  看起来像“红”，其实什么都没测）。#21/#22/#23 各撞过一次才修好。
- **`.gitignore` 会把题面吞掉**：`drop/` 的 9 份期望输出 `*.out` 被仓库根那条为 C 的 `a.out` 写的
  `*.out` 全忽略了 —— 本地跑几遍都绿，干净克隆里第 1 段根本没跑。教训不是"记得 `git add -f`"，
  是门要能自己看见缺题面：`drop/check.sh` 破坏 Z7 把整棵树拷走、删掉所有 `*.out`、重跑，要求红且说清缺哪个文件。
  提交前 `git status` 的复核是发现它的唯一机会 —— 新加的题面文件如果没出现在 status 里，就是没进仓库。
- **数字写错和数字变了要分开说**：第 3 段用 `换行数 + 1` 数行，文件以换行结尾时多报一行，
  于是所有文档里的 `spec.txt` 行数都写成 153（真实 152）；同一批文档还把 `drop/check.sh` 写成「约 6 秒」，
  那是早期一次性估数，重测三遍是 1356–1371 ms。这类是算错/没重测，不能混进"本轮把 X 从 a 加到 b"。
  凡是文档里的数，要么当场跑出来，要么标成估数并写明怎么复测。（v0.40 又犯了一次同类：写完文档才改定义，
  文档里的 token 数、探针数、门时间当场过期 —— 改完必须回头重跑一遍再落数。）
- **破坏测试崩掉时看起来和成功一模一样**：给门加 `examples/http.dr` 之后，Z6 在临时树里找一份不存在的
  `http.out`，`NameError: os` 崩在非零退出码上，脚本把这当成了"抓住了"。破坏测试的红必须**归因到它声称的
  那个原因**（看诊断文本），崩栈也算红但算假红；这也是主工程 `sabotage-sup.sh` 早就有的那条纪律的复发，
  说明它没写进 `drop/check.sh` 的注释里 —— 现在写了。
- **表面探针查不出行为**：它只回答"定义里有没有这句话"。`bytes()` 定义写「<=255 就是一个字节」，实现一律
  UTF-8 编码，`bytes("ä")` 定义 1 字节 / 实现 2 字节，128 条探针全绿。能抓住它的只有一个活样本
  （`len(bytes("\xe4"))` → `1`）。凡是"定义里写了一条可数的规则"，就要有一个数出来对的样本。
- **两条编码路 = 一个真 bug**：`request` 是一字节一字符的 latin-1，`reply` 走 `encode("utf-8")`，
  POST 回声就乱码。"同一件事只有一种写法"在实现层的版本是**同一条规则只能有一份代码**：现在
  `bytes()` 和 `reply()` 共用 `_wire()`。删语法糖的时候不顺手删重复实现，糖还会从实现里长回来。
- **协议严格性必须配一个"死等多久"**：定义说"行分隔只认 CRLF"是对的，但没配超时，一个只发 LF 的请求
  能让服务器和探针互相等到天荒地老（门从 1.4 秒变 5 秒以上）。加 `IDLE_SEC = 10` 断连 + 探针半关闭之后
  回到 2.4 秒（加上本轮新配的 Z11 嵌套跑是 2.5 秒），台账一字没变。凡是"我拒绝处理"，都要回答"拒绝之后多久放手"。
- **收紧必须配一条能撤销它的破坏测试**：删掉 `map` 这类名字，如果只写一句"没有这种东西"，下一轮加回来
  没人会红。Z8/Z9/Z10 干的就是"把删除撤销 → 门当场红"。**只能靠我下次记得的约束等于没存在过。**
- **「独立」写在文档里就不算独立**：v0.39 的文档里那句 grep 命中 0 处，是作者自己手跑出来的；本轮实现的
  一句注释里写了仓库别处的目录名，那句 grep 的模式恰好不含它，于是本地、CI、文档三方都不会红。现在这条
  检查进了门的第一段，并有 Z11 拿「往定义里塞一句引用」证明它真的会红。凡是靠“我记得去查”的判据，
  都要先变成一条会红的东西，再谈它守住了什么。

**以下四条是 v0.41（把协议搬进库）新增的**：

- **「用这门语言写东西」会把语言的边界照出来，纸面上看不出来**：三条只有写库的人才会撞上的洞 ——
  (a) **尾位是浅的**：实现只认"函数体最后一句是自身调用"和"最后一句是 `if`、两支里是自身调用"，
  往 `if` 里再套一层或藏进块表达式就不是尾位，70 KB 首部扫描当场 `E13 —— 往里缩到第 201 层`。
  (b) **没有赋值 = 库不能持有状态**：想照 v0.40 的样子在库里写全局 `PEER` / `RESP` 再赋值，直接 E3；
  接口必须变成**返回一个值**（`handle(req, peer)` → `[状态, 正文]`）。
  (c) **没有 `ord`**：数字字符的值只能查 `"0123456789"` 这张表的位置。
  这三条都不是 bug，是语言的形状；教训是**语言的可用性只能靠用它写非计算程序来验收**，
  冷读和自测都发现不了"少一个 `ord` 会让解析器多写八个函数"。
- **宿主说"第一个换行切开"就是字面意思**：以为正文里还能再放一个哨兵字节，于是发出
  `handle + "\n" + body + "\x00"`，线上真多出来两个字节。凡是"一条分隔规则"，就要问它**切几次**；
  切一次的规则只能有一个分隔符，别指望第二个。
- **拼接多个输入文件时，行号是最容易悄悄错一位的东西**：`run_files` 用 `"
".join(src)`，而每个文件末尾
  本来就带换行，于是库和程序之间凭空多一行，程序第一行的错报成 175 而不是 174 —— **台账、文档、文件三处
  的行号当场全部对不上，而门是绿的**（因为三处都写了同一个错数）。修法不是"改文档里的数"，是改拼接
  （先 `rstrip("\n")` 再拼），然后重抽台账。凡是"跨文件引用一个行号"，都要有一处机器能数到的东西钉着。
- **台账的行号与库的长度耦合**：`tests/http.expected` 里那三条报错行（本轮是 `第 171 / 171 / 142`）
  是"库 170 行 + 程序里的位置"算出来的。**往 `lib/http.dr` 里加一行，它们就全体 +1**，门会红在"对话不一样"
  上（不是假绿，是要重抽）。下次改库前先想清楚：这是行为变了，还是只是行号挪了 —— 前者要修代码，后者要重抽。
  v0.42 就正好撞上一次：为了写清 `read_head` 那条判据给库加了 3 行，三条数从 `168/168/139` 挪到
  `171/171/142`，**线上传输字节一字没变** —— 这就该写成"重抽台账"，不该写成"行为变了"。
- **表面探针查的是"定义里有没有这句话"，永远查不到"实现有没有做到"**：`drop.py` 的探针里一直有
  「局部函数不追改」这一条原话，绿了三轮；而实现恰恰在这条上反着做（重名 `let` 就地覆盖，早已写好的
  `fn` 跟着看到新值）。本轮不是门抓到的，是**第二份宿主**（另一台机器上另一个人只读同一页定义写的）
  在这个用例上给出不同输出才暴露的。教训：一条规则只有"另一个实现"能验，探针只能验我自己有没有抄对。
  这就是 `cs/conform.sh` 这台秤存在的理由，也是它比"再多写十条单元测试"值钱的地方。
- **改绑定语义，必须连带想清楚尾位**：把 `let`/`fn` 重名从"就地覆盖"改成"另起一层"之后，
  `tests/reader2_2.dr` 死循环。根因：尾位调用的实参仍在函数自己那一层求值，而块里 `let b = ...`
  从第二圈起已经搬进遮层 —— 尾位读到上一圈的 `b`，跳回去不前进。这门语言**唯一的循环就是尾调用**，
  所以任何作用域改动都要在尾递归程序上跑一遍才敢说绿（光看单元测试全绿是不够的，它当时确实全绿）。
- **破坏测试自己不许吐堆栈**：本轮 Z16 的锚点字符串因为一次代码重建对不上，`assert` 直接把 Python
  traceback 打在门的输出里 —— 而 `drop` 的定义明写"一红就停、不许堆栈"，我自己那条纪律反倒破了。
  更糟的是 shell 那层没查内嵌 python 的退出码，补丁没打上时会继续往下跑成"假绿"。修法：所有
  `assert` 换 `if not ...: sys.exit(一句原因)`，每段 heredoc 之后紧跟 `[ $? -ne 0 ]` 当场红。
  **要求别人做到的事，破坏测试这一层要先做到。**
- **未提交的收紧，清理实验时不许用 `git checkout -- <file>`**：本轮一句"回滚一个实验性改动"把 v0.42
  半天没提交的解析器改动全冲掉了，重建时漏了三处执法点（`print` 与 `(` 之间、`if` 与 `(` 之间、
  名字与 `=` 之间），是秤上那 25 个跨行形状抓出来的。规矩：动 `git checkout`/`reset --hard` 之前
  先 `git stash` 或临时分支，**尤其是这一轮还没提交过的文件**。

- **破坏测试自己也会留洞：Z13 只管库，不管口子**：本轮加了"库里不许出现第八个宿主命令"之后，我以为这条
  纪律已经守住了。写文档时才看见另一半：**实现 `HOST_CMDS` 加宽到八个、库里一次都没用**，门照样绿 ——
  因为探针只查"定义里有没有「命令只有七个」这句话"。修法是在对账里加第三条双向比（实现的表 ↔ 定义那七个
  名字，宽了/少了/名字没在定义里出现过都不拢）+ 新增 Z14。**教训：一条"不许越界"的检查，必须同时问
  「墙的另一边谁在看守」** —— 只查调用方不查被调用方，等于把口子留给自己。
- **分层是有价格的，价格要当场量出来，不能写成"多测了东西"**：同机同一条命令，门从 2.48 秒涨到 9.2 秒。
  第一反应是"本轮多跑了两条嵌套门（Z12/Z13/Z14）"，但把 v0.40 的树 `git archive` 出来同机重跑再逐请求计时，
  真相是**那条 70 KB 首部的用例在 drop 里逐字符扫描要 4.63 秒**（协议在 Python 里时整个台账 0.22 秒）。
  凡是本轮出现"变慢/变大/变多"，先同机重跑旧版本再说原因；把 `git archive HEAD` 当成量尺的一部分，
  而不是只比历史文档里的数。
- **删语法会传染到回归语料的性质**：`drop/tests/reader2_*.dr` 原文用了被删掉的 `filter`/`fold`/匿名函数，
  不改就跑不通；改了之后它们不再是"读者一次写对"的证据，只是"删糖后仍能表达"的回归。
  证据的性质变了要显式改账（DROP.md §5、VALIDATION §9 都写了），不能继续按原来的名目报数。

- **秤上的 `set -e` 会拿一段的红遮掉另一段的证据**：`conform.sh` 原本一遇红就退出，而它四段里最硬的
  是第 3 段（真客户端打真字节）。结果第 2 段一红，第 3 段从没跑过，实录里那 3 行行号漂移藏了一整轮 ——
  我还在文档里写过"实录对上"，那是第 2 段还绿时量的，早过期了。**教训：多段仪器要"全部跑完再算账"，
  最后一次性报红在第几段**；红一条没松，但证据一条不许被别段的红挤掉。凡是 `set -e` 串起来的段，
  都要问一句"前面红了，后面那段还看得见吗"。
- **注释和标签里的数字也是账，也要能复查**：`conform.sh` 的耗时那行写着 `spec.dr`「含 count(50000) 与
  100000 层尾调用」，我看它顺眼就把它当"本轮变慢"的旁证抄进文档 —— 实际上 `spec.dr` 里只有
  `count(50000)`（162 ms），十万层那份是另一个文件 `cs/probe/e13tail.dr`（python3 84 s / dotnet 124 s），
  而且这段根本没跑它。**教训：报一个数之前先看它挂在哪条命令上**；标签、注释、文档标题里的事后归因
  和代码里的数字一样，都需要一次实测，不然就是自己给自己造的假证据。

- **改一份"说明某条错报在第几行"的文件，本身会移动那个第几行**：我给探针 `attr_body.dr` 的注释补一句
  更正，多写了一行，`v[1]` 那个记号从第 5 行跳到第 6 行 —— 探针当场自相矛盾，两份宿主一起报新行号来打脸。
  这类文件（行号就是断言的一部分）改注释必须**保持行数不变**，改完立刻跑一遍看落点还说不说得通。
  顺带一条：注释也占行、行号照数，这是两份宿主自己纠正出来的 —— 我原本在注释里写"必须报第 1 行"，
  两边都不同意。**文档里那些"第 N 行"的数字，改文件之后要重新量，不许沿用。**
- **"两份实现一致"不等于"定义说了算"，而且这种洞不会红**：漂移会红，巧合一致永远绿。
  本轮秤全绿之后反而查出 5 处两边各自挑读法、恰好挑一样的形状（`
`、顶层同行两句、跨行错报的行号落点、
  `host` 少参先查 arity 还是先查命令表、注释占不占行号）。**教训：一致性检查只能证伪"定义没写清"，
  不能证明"定义写清了"**；想要后者，得让第二份实现把它自己"没有依据所以挑了一种"的清单也交回来，
  那份清单才是定义的真实缺口账（本轮那份 40 条 + 交回时补的几条，就是靠它把 §10.6 撑起来的）。
