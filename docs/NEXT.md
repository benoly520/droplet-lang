  跑法、错误码、内置、宿主口子全在这一页里；`drop/` 不引用仓库里任何其它文件（第一段那条 grep 是门）。
- **两份宿主，一份定义**：`hosts/python/interpreter.py`（1,192 行，参考实现）与
  `hosts/csharp/interpreter.cs`（1,692 行，另一个人只读 `spec.txt` 从零写的）。
  对账仪 `sh drop/conform.sh`：语料 11/11 逐字节、报错样本 73 个 0 漂（同行同码 57）、服务器实录 88 行逐字。
  **本机没有 dotnet，这段明说没跑** —— 那不是绿，是没测。
- **API 面钉成表**：`drop/api.json`（14 码 / 8 内置带 arity / 7 宿主命令 / 22 保留名 / 退出码 0·1·2），
  由 `api_check.py` 三向对账：跟定义逐字比、跟实现逐字比、再拿真程序打（少一个实参必须是 E2）。
- **门**：`sh drop/check.sh` 五段 + **十八条破坏**，今日同机三遍 **18.13 / 18.24 / 18.13 秒**。
  （上一轮记的是 15.5，本轮早先一次 16.7 —— 这是同一台机器不同时段的抖动，**没单独归因**，
  按规矩照实记：这是变差，不是改善。）
- **编译器有了第一个产物**：`codegen/dropc.c`（741 行 C）把子集编成**裸 ELF** —— 自己排字节、自己写 ELF 头，
  不经过 `as`、不经过 `ld`、不经过 python。产物没有 libc、没有动态链接，运行时只有 `write`(1) 与 `exit`(60)。
  实测：25 万次尾递归 **545 B / 332–336 KB / 2.30 ms**（参考实现 14,248 KB / 1,035 ms）；
  `examples/fact.dr` 原样 **643 B / 332–336 KB / 0.46 ms**（参考实现 14,184 KB / 25.9 ms）。
  判据 `python3 tools/codegen_check.py`：4 份语料逐字同输出 + 3 份子集外样本拒绝在第 2 行 + 无 INTERP 段。

## 2. 待办（按优先级）

### P0 · 第三轮冷读：换一个没读过任何历史的读者

`drop` 的定义写得完不完，到现在仍没有**读者口径**的独立读数。v0.42 那份 C# 宿主算一次独立阅读，
但它读的目标是"怎么写解释器"，不是"怎么用它写程序"—— 它列出的含糊全是词法/语法边界，一条关于库或惯用法。

1. 开一个全新上下文的读者，**只**给 `drop/spec.txt`，禁止读 `hosts/python/interpreter.py`；
2. 让它写 4 份程序（含一份故意写错看报什么码）+ 交回「不得不猜」的清单；
3. 两档题：(a) 只读 `spec.txt` 写出能应答 `GET`/`POST` 的程序，**不许读 `lib/http.dr`**；
   (b) 允许读库，把程序接到 `http_serve()` 上 —— 考的是"库的接口能不能只靠读代码学会"；
4. 逐份机械跑，绿/改几次才绿/FAIL 都要写进 `drop/tests/` 或 DROP.md，不许只报"看起来行"；
5. 猜的次数如果比第二轮（25 条 → 21 闭 → 7 新洞）还多，就**在 1,500 之内重写定义**：加一句必须删一句。

验收线：新增的读者程序进 `drop/tests/`，`sh drop/check.sh` 仍全绿，DROP.md §5 有第三轮的实测数字。
（上一轮试过开新读者：`create_agent` 被「并发子线程上限 25」拒了 —— 要么先回收线程，要么下一个会话做。）

### P0b · 分层的价格还没还

那条 70,000 字节首部的用例现在单条 **4.63 秒**（协议在 Python 里时整条台账 0.22 秒，现在整条 4.96 秒），
因为 `find_blank` 是一个字符一次解释调用地在 drop 里走。两个方向都能治，都还没做：

1. **按块扫**：库里一次 `recv` 拿回来的整块先数 `len(buf)` 再决定要不要重扫，而不是每字符一次递归；
2. **让宿主多给一点**：`recv` 现在固定一次 4096 字节，定义里那句「阻塞到至少一个字节」并不禁止"能给多少给多少"。

动第 2 条就是动定义，必须先删一句别的（预算 99.8%）。判据不变：`tests/http.expected` 的线上字节一字不许变，
门时间必须降下来 —— 降不下来就是没治到根因。

### P0c · 预算已经挡住"把含糊写清楚"了 —— 三条路必须选一条（用户裁决）

剩下 5 处「两份宿主各猜了一种读法、恰好猜一样」（DROP.md §10.6）：
行尾多一个 `\r` 算不算行尾、顶层同一行写两句要不要正面允许、**跨行的错报在哪一行**、
`host` 少给参数先 E2 还是先 E14、注释占不占行号。前两条已经能靠推理，后三条推理不出来。

**价格是量出来的，不是感觉的：** 写清楚其中两条要 10 个 token，而现在能腾出来的只有 3 个。

| 路 | 做什么 | 代价 |
| --- | --- | --- |
| (a) 抬预算 | 1,500 → 1,510 或更多 | 这是**放宽**，按规矩得当收紧报：必须给"为什么这次可以"，且「预算 = 读完这一页就会用的成立条件」要重述 |
| (b) 删一句真的换 token | 候选：第 125 行那半句观察不到的例外（腾 3）、`str` 与 `print` 对表的两种写法、七个 `host` 命令里 `peer` 能不能由 `recv` 承担 | 每删一句都要连带改探针与语料，且必须证明"没变难用" —— 这是真活，不是腾字 |
| (c) 不动定义 | 5 处继续记在文档里当已知含糊 | 零成本，但"同一页定义长出第二份宿主"这句话的可信度就靠这 5 处撑着 |

维护者本轮按 (c) 走，**没有偷偷改预算，也没有偷偷加句子**。下一轮要么用户点头走 (a)，要么老实做 (b) 的一次删换。
不许用"补一句定义"的名义把预算当橡皮筋。

### P1 · 编译成什么：那张指令表还没回答（用户裁决）

`codegen/dropc.c` 直接产机器码，**跳过了字节码这一层**，所以 BUILD.md §4 的 A–F 仍然是选择题。
待裁的两件：

1. **要"换平台"还是要"不背运行时"**：B（自带字节码 + 小 C VM）两边都留一点，D（原生码）把后者拿满、前者交出去，
   而 D 与"同一份定义长出第三个宿主"这条线互相排斥（宿主可以换，机器码不能）；
2. **指令集条数上限先定后写**：一张穷举的表（表外操作码是错误），上限要在写之前定，不然「换宿主」就是空话。

价格已经量过：字节码声明部分 ≈33 token，含 24 行指令表 ≈201，再把 P0c 那 5 处焊平 ≈30–40，
合计 **≈230–240**，而现页余量是 3 —— 所以这必然牵动 P0c 的前两条路之一。

### P2 · ⑧ 只有尺，没有线

`tools/footprint.py` 能报峰值 RSS / 启动耗时 / 磁盘，也能收 `--budget-mb/--budget-ms`，但**预算还没钉**。
钉预算这件事按 BUILD.md §3 的规矩来：同一个程序、同一把秤（`tools/rssshim.c`，fork + execvp + wait4），
先定数再改实现；数字变差要按放宽报。

## 3. 一轮工作怎么算完

1. `sh drop/check.sh` 绿（五段 + 十八条破坏，每条都要先断言补丁落到目标上、再断言红在它声称的那一条上）。
2. `sh drop/conform.sh`：有 dotnet 就四段全绿；没有就**明说没跑**，不许写成绿。
3. `python3 tools/codegen_check.py` 绿（动了 `codegen/` 时必跑）。
4. 动了 `spec.txt`：token 仍 ≤ 1,500（`check.sh` 第 3 段当场算）、两份宿主行数、`conform.sh`、
   `api_check.py` 全部重跑 —— 定义改一个字，这三样都可能跟着动。
5. 动了编译器：产物与参考实现**逐字同输出**，三份子集外样本仍拒绝在第 2 行，`readelf` 里仍 0 个 INTERP 段。
6. 数字进文档：同机重跑，注明次数；变差就写成变差，不许把"换了实现"记成"优化"。

## 4. 坑（踩过的）

- **定义里的例子必须机器抽出来跑**，否则作者会在自己的定义里写非法程序：`spec.txt` 里带 `> ` 的行逐字抽成
  `examples/spec.dr`，与提交版逐字比，再跑一遍比输出（第 4 段 + 破坏 Z5）。
- **表面探针查的是"定义里有没有这句话"，永远查不到"实现有没有做到"**：`hosts/python/interpreter.py` 的探针里
  一直有「局部函数不追改」，绿了三轮，而实现恰恰在这条上反着做；本轮不是门抓到的，是**第二份宿主**抓到的。
  一条规则只有"另一个实现"能验，探针只能验我自己有没有抄对 —— 这就是 `conform.sh` 存在的理由。
- **改绑定语义，必须连带想清楚尾位**：把 `let`/`fn` 重名从"就地覆盖"改成"另起一层"之后，
  `tests/reader2_2.dr` 死循环 —— 尾位调用的实参仍在函数自己那一层求值，而块里 `let` 从第二圈起搬进遮层。
  这门语言**唯一的循环就是尾调用**，任何作用域改动都要在尾递归程序上跑一遍才敢说绿。
- **「用这门语言写东西」会把语言的边界照出来，纸面上看不出来**：(a) **尾位是浅的**（往 `if` 里再套一层就不是尾位，
  70 KB 首部扫描当场 `E13`）；(b) **没有赋值 = 库不能持有状态**，接口必须变成"返回一个值"；
  (c) **没有 `ord`**，数字字符只能查表。三条都不是 bug，是语言的形状。
- **宿主说"第一个换行切开"就是字面意思**：以为正文里还能再放一个哨兵字节，线上真多出来两个字节。
  凡是"一条分隔规则"，就要问它**切几次**。
- **拼接多个输入文件时，行号是最容易悄悄错一位的东西**：每个文件末尾本来就带换行，库和程序之间凭空多一行，
  程序第一行的错报成 175 而不是 174 —— 台账、文档、文件三处的行号当场全对不上，**而门是绿的**。
  修法是改拼接（先 `rstrip` 再拼）再重抽台账，不是改文档里的数。
- **台账的行号与库的长度耦合**：`tests/http.expected` 里那三条报错行是"库 170 行 + 程序里的位置"算出来的，
  **往 `lib/http.dr` 加一行，它们全体 +1**，门会红在"对话不一样"上。这是"要重抽台账"，不是"行为变了"。
- **破坏测试的"红"必须归因到具体工具**：注入代码少个 `#include` 也会"红"，那是编译错误冒充检查成功。
  每条破坏都要断言诊断文本，且必须有一条"本该全绿"的干净参照。
- **破坏测试自己不许吐堆栈**：Z16 的锚点字符串因为一次代码重建对不上，`assert` 把 traceback 打在门的输出里；
  更糟的是 shell 那层没查内嵌 python 的退出码，补丁没打上时会继续往下跑成"假绿"。先断言补丁落地，再断言红。
- **`.gitignore` 会把题面吞掉**：`drop/` 的 9 份期望输出 `*.out` 被根目录那条为 `a.out` 写的 `*.out` 全忽略了 ——
  本地跑几遍都绿，干净克隆里第 1 段根本没跑。门现在能自己看见缺题面（破坏 Z7），提交前 `git status` 是唯一复核。
- **临时树里跑的检查要显式传 `--root`/`--spec`**：从脚本自身位置推 `ROOT` 的检查器会指到临时树外面，
  表现为 `FileNotFoundError` —— 看起来像"红"，其实什么都没测。
- **委派有并发上限，实验要能降级**：第三轮冷读开不出新读者（25 线程满）。别把结论挂在"读者会回话"上：
  先用机械复核把能测的测掉，读数欠账显式记成 P0。
