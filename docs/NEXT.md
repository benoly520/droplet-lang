### P6 · 核心命题的最小实验（0 行代码，需要人配合）—— v0.28 已演练，未算完成

- **v0.28 演练结果（详见 `docs/VALIDATION.md`）**：题面与流程都跑通了，
  `verify` / `explore` 在真实任务上出得来账；但 0/3 收敛，原因是 `explore` 的判定比判据 A 严
  —— 见 P15 与 D0 §3。同源候选使"首次通过率"无信息量，故 P6 仍要求**外部模型独立取三份候选**复跑。

- **为什么要有这一条**：到 v0.23，工具链能证明「**一份**实现被意图约束住了」（verify 的取值 + 四类变异），
  也能证明「**几份**候选里哪一份活下来」（explore）。但整个项目对外承诺的那句话 ——
  人写意图、AI 生成候选、验证器挑选 —— **从来没有在真实任务上跑完过一次**，
  §7.8.3-5 那条「判断 A 的人工成本」也一直没有数字。这是唯一一项**不能靠写代码推进**的证据。
- **材料（必须落在 D0 子集里，否则测的是语言缺什么，不是方法好不好）**：
  1. 纯谓词类：`fn key_ok(k: str) -> bool`（key 白名单，`[a-z0-9_-]{1,32}`）
  2. 分支密集类：`fn tag_for(e: SomeError) -> u64`（错误变体 → HTTP 码的投影，含 default）
  3. 边界敏感类：`fn can_write(prev: u64, if_match: u64, body_len: u64) -> bool`（预条件 + 上限）
  三题都只要写一个函数体，**不涉及循环、模块、能力调用** —— 也正好是当前语言装得下的全部形状。
- **流程（每题一次，共 3 次）**：
  1. 人只写签名 + `requires` + 2–3 条 `example`，**不写实现**；
  2. 让模型独立出 3 份候选（每份只看意图，不看彼此），存成 `a.dlt` / `b.dlt` / `c.dlt`；
  3. 逐份 `droplet verify`，记 PASS / FAIL / skip；
  4. `droplet explore a.dlt b.dlt c.dlt`，记存活数与分歧点名；
  5. 若欠定或零存活：人补 example（记**补了几条**、补的时候看的是工具给的哪条反例），回到 3；
     最多 3 轮，仍未收敛就记为「意图欠定」——**这个结果本身也是结论**。
- **记什么（一张表，每行一个任务）**：候选数 / 首次通过的份数 / 收敛所需轮数 / 人补的 example 条数 /
  人的总分钟数 / 最后存活几份。**不记**模型版本与提示词风格（那会让结论随模型漂移）。
- **判据（先写死，避免事后解释）**：
  - 三题都在 2 轮内收敛到唯一存活 → 方法在这类任务上成立，可以去做更大的验证；
  - 多数题需要人补**微妙的** example（例如只有边界翻转才分得开） → 工具的产出是**反例对**，
    §7.8.3 A 的「不自动挑」是对的，但"收敛"这件事仍然靠人，成本要照实算；
  - 多数题在 3 轮内不收敛 → 意图表达力（当前只有 bool 表达式）是瓶颈，
    优先级应该是 §5.10 的表达力，而不是继续加变异类。
- **成本**：半天到一天的人力，0 行 `code/lang`。结果写进新建的 `docs/VALIDATION.md`（跑完再建，现在不建）。

  可证伪形式 —— 而它**从未被测量过**（`grep -rn "H1" docs` 只有条文，没有数字；
  设计里承诺的 `spec.json` 也不存在）。这比再加一个语法重要。
- **怎么测**：同一批任务（≥6 个，覆盖纯谓词 / 分支密集 / 边界敏感三类，见 P6 的题面），三组材料：
  1. **完整 SPEC**（现在是 1300+ 行）；
  2. **精简**：`examples/hello.dlt` + `webapi/src/*.dlt`（95 行）+ 错误码表 + 能力表；
  3. **只有签名与意图**（不给任何示例）。
  每组各出 3 份候选，跑 `check` / `build` / `verify`，记"一次写对率"与"首次通过所需 token"。
- **判据（先写死）**：
  - (2) 与 (1) 差距 < 10% → 文档冗余严重，`spec.json` 才是该做的事；
  - (2) 明显差于 (1) → 叙述里藏着必要信息，先补精简文档再谈减语法；
  - (3) 崩掉 → 说明"读示例"是主要学习通道，示例集应当被当成一等交付物维护。
- **顺带产出**：H1 的第一个实测数字（精简材料 (2) 的 token 数），填进 SPEC 的 H1 行。

### P8 · 证据卡 `evidence.json`（先定格式，代码等预算）

- **要解决什么**：SPEC 附录 D.7 描述了"人只审目标、不审实现"的形态，但**证据现在是散的** ——
  样例在 `verify` 的输出里、分歧在 `explore` 的输出里、权限在 `contract` 的 JSON 里、
  变异在标准输出里，没有一张可存档、可 diff、可签字的卡。这不是架构问题，是打包问题。
- **格式（先写在这里，实现时再定 schema 版本）**：
  ```
  { "source": "<sha256 of .dlt>", "runtime": "<sha256 of assets>", "verifier": "<sha version>",
    "intent": { "added": [...], "removed": [...] , "changed": [...] },
    "capabilities": { "added": [], "removed": [] },        // 唯一会泄漏的方向
    "verify": { "cases": 9, "ran": 9, "fail": 0, "skipped": [] },
    "explore": { "candidates": 3, "survivors": 1, "probes": 40, "divergent": [] },
    "mutation": { "mutants": 14, "caught": 12, "miss": ["c.go:41 常量 8 → 9", ...] },
    "budget": { "h8_lines": 7993, "binary_bytes": 0, "idle_rss_kb": 1852 } }
  ```
- **三条纪律**：① `skipped` 与 `miss` **必须逐条列出**，不许汇总成"通过"；
  ② `capabilities.added` 非空时卡片必须显眼（这是唯一能越权的方向）；
  ③ 四元组 hash 缺一个就不算证据（D.7.3 第 4 条）。
- **成本**：约 120–150 行（新命令 + 从三条现有命令抽结论），现在余量 7 行 —— **等预算**。
  在此之前，`evidence` 应该由人手工拼（`verify` + `explore` + `contract` 三份输出），不要假装有。

### P11 · 目标那一面现在是空的：先解"验证器进不去服务"（SPEC 附录 D.9 派生）

### P12 · 让 `boundary` 上的 example 进 oracle（E11 收紧的前置）

### P14 · `verify` 的存活变异应附带一个能翻面的输入（要预算）

### P15 · `explore` 的收敛判定比判据 A 更严（实测踩空，属实现偏差）

- 判据原文（§7.8.3-1）：**存活候选之间有外部可观测差异**才失败，且必须带反例对。

- 实测依据（VALIDATION §4 第 1 条）：三题最终存活者外延相同
  （`n >= 1` vs `n > 0`、`<= 8388608` vs `< 8388609`、通配臂 vs 全列举臂），

- 正确出口是把结局分成三种：唯一存活 / 多存活**且有分歧**（= 欠定，走 A）/

  第三种怎么收口要人拍板：算通过？算警告？还是算一条新的 `E12` 子类？
- 代价：`cmdExplore` 的分流 + 一行输出，约 10–20 行；余量 7 行 → 先谈 P5。

  不能写进 `.u.ok`（C 会报 `incompatible types`），要写进联合的 `.tag`。判据是表达式类型是不是
  当前返回联合里的错误成员（`isErrItem`）。D2 第一次编译就是踩在这里
- **412 与 405 不是同一条路**：405 现在由 handler 的 tag 派生（空 body），412 仍由运行时在进
  handler 之前发出（文本 body）。写测试时别把「tag 派生 = 空 body」推广到 412
- 批量改 `check_test.go` 里的服务样例：先换签名（`-> Response | ApiError` → `-> bytes | ApiError`），
  再换构造（`return Response{…}` → `return b""`），最后删 `Response` 类型声明 —— 顺序倒了会
  留下「签名是 bytes、函数体还返回 Response」的中间态，`expectOne` 会因此报 2 条错而不是 1 条
