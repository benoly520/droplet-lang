# VALIDATION：核心命题的第一次完整演练（P6）

> 这份文档只记**跑过的事实**。P6 要回答的是项目对外的那句话 ——
> "人写意图、AI 生成候选、验证器挑选" —— 到底跑不跑得通。
> 第一次跑的时间：2026-10-31（v0.28）。题面、候选、命令输出全部在
> `docs/validation/p6/` 里，可以照 §5 重跑。

## 1. 先说这次实验不能证明什么

**候选是我（同一个模型）生成的，意图也是我写的。** 生成器与出题人同源，
所以"首次通过率""收敛轮数"这两个数在这份报告里**只反映方法学能不能跑，不反映方法有多好**。
真正的结论需要作者从自己不可控的模型独立取候选复跑（NEXT P6 仍算未完成，见 §6）。

这条声明放在最前面，是因为它决定了下面所有数字的解释方式。

## 2. 三题（都在 D0 子集里）

| 任务 | 签名 | 人写的意图（除签名外仅此） | 形状 |
| --- | --- | --- | --- |
| A | `fn size_ok(n: u64) -> bool` | 3 条 `example`：`size_ok(0) == false`、`size_ok(8388608) == true`、`size_ok(8388609) == false` | 边界敏感 |
| B | `fn retryable(e: ApiError) -> bool` | 3 条 `example`：`IoError == true`、`PreconditionFailed == true`、`NotFound == false` | 分支密集 |
| C | `fn can_write(prev: u64, if_match: u64, body_len: u64) -> bool` | 3 条 `example`：`(0,5,10) == false`、`(5,5,10) == true`、`(5,4,10) == false` | 三参数决定 |

三个任务都刻意**不涉及循环、能力调用、模块** —— 也正是当前语言装得下的全部形状。
每题三个候选（`a.dlt` / `b.dlt` / `c.dlt`），各用一种自然写法：早守卫 / 合取 / 逐层嵌套 /
通配分支 / 全列举分支。候选在跑工具**之前冻结**，之后没有为了让它过而改过实现。

`intent.dlt` 里额外放了一个**占位实现**当靶子（看 §4 第 3 条）。

## 3. 结果一览

| 任务 | 首次通过 | 自动输入 | 第 1 轮存活 | 人补的 example | 最终存活 | 存活者可否观测地不同 | 变异 MISS 账 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| A | 3/3 | 9 条 | 3 | 1 条 | 3 | **否**（三个候选等价） | 1 → 0（补的那条命中） |
| B | 3/3 | **0 条** | 3 | 3 条 | 2 | **否**（a 与 b 等价，c 已被否） | 14 → 12（剩的全是等价变异） |
| C | 3/3 | 25 条 | 3 | 2 条 | 3 | **否**（三个候选等价） | 4 → 0（第 1 条没命中，第 2 条命中） |

命令：`droplet verify <候选>`（样例 + 四类变异）、`droplet explore a.dlt b.dlt c.dlt`（样例对齐 + 生成输入）。
候选之间**没有产生一条分歧**（除了 B 里 `Conflict` 那条我特意让人补的样例点出来的），
自动输入也没抓到任何东西 —— 因为要比较的候选本来就没有行为差异。
**0/3 收敛到唯一存活**，三题都退出码 1（判据 A：工具不替人挑）。

## 4. 撞出来的六条事实（预写的三条判据都没覆盖它们）

1. **`explore` 的收敛判定比判据 A 更严，而且严在了一个不可能满足的地方。**
   SPEC §7.8.3-1 写的是：存活候选之间存在**外部可观测的行为差异**才失败，
   且失败必须携带**反例对**。三题最后存活的候选却都是**外延相同**的函数
   —— A 的 `n >= 1` 与 `n > 0`（u64 上恒等）、C 的 `body_len <= 8388608` 与 `< 8388609`、
   B 的"通配臂"与"六个变体全列举"。没有任何输入能把它们分开，
   于是 `explore` 报"欠定 —— 补一条 example 让它们分开"（退出码 1）时，
   **它要人补的东西根本不存在**。这是实现比判据严、且把判据的一条前提踩空了：
   判据 A 从来没有要求"唯一的一份写法"。
   正确的出口是把结局分成三种（唯一存活 / 多存活**且有分歧** = 欠定 /
   多存活**且无分歧** = 未证分歧），第三种必须写明"判定只用了这些输入"——
   无分歧 ≠ 等价。登记为 P15，并作为一条 D0 偏差记进 §3 工具链。
   注意：等价本身是我按语言语义推的，工具里没有等价判定，我也没有 —— 这条只能算论证，不算测量。
2. **"首次通过率"这个指标在自产候选下没有信息量**（9/9 通过）。要它有意义，
   候选必须来自与出题人无关的模型；否则测的是我自己的自我一致性。
3. **"人只写意图 + 空实现"这份工件编不出来。** 占位实现体不引用参数，
   生成的 C 在 `-Werror=unused-parameter` 下直接失败（`droplet verify intent.dlt` 报的是
   `cc 失败：unused parameter 'v_n'`）。D0 里没有"未实现"这个标记，
   所以意图只能寄居在带实现的候选文件里。这解释了为什么 `intent.dlt` 的占位实现
   必须写成"用到参数但规则不全"（A 用 `n > 0`、C 用 `(if_match == prev) && (body_len > 0)`）
   —— 而它们确实被样例否掉了（A 否 1 条、B 否 2 条、C 否 2 条），"意图有牙齿"这一点在三个任务上都成立。
4. **`MISS` 有两类，工具现在不区分 —— 人会为第二类白补样例。**
   一类是**真缺口**，补一条样例就堵：A 的 `>= 1` → `> 1` 被新加的 `size_ok(1) == true` 抓住；
   C 的 4 处 MISS 全在 `prev == 0` 那道守卫上，补 `can_write(0, 0, 10) == false` 后
   `mutate: 2 处变异，0 处没被抓住`（三个候选都归零）—— 这一条我第一轮没补到，
   我先补的是上界那条，`MISS 4 → 4`，白补。
   另一类是**等价变异**：改动不可观测，任何样例都堵不上 —— B 里"把 `return false` 的分支体
   清空 / 删掉"共 12 处（通配臂 ×2 + 四个具名 false 臂 ×2 + c 的通配臂 ×2），
   函数返回值一模一样，`14 → 12` 之后再也降不下去。
   总账：**人补 6 条样例，3 条起效**（A 堵 1 处、C 堵 4 处、B 否掉 1 个候选），3 条无效
   （C 的第一条打偏、B 的另外两条动不了等价变异）。
5. **非数值参数的分歧，工具一条也抓不到。** B 的自动输入是 **0 条** —— 取值池只覆盖
   u64 / i64 / bool，`ApiError` 这类 sum 参数被排除（D0「候选收敛」第 ① 条边界）。
   结果：c 把 `Conflict` 判成可重试这件事，**只有靠人手写一条 `example` 才暴露**。
   这条边界在真实任务上的代价第一次有了具体形状。
6. **`verify` 的 `MISS` 只给位置，不给能翻面的输入。** 于是"补哪条样例"完全靠人从
   位置 + 变异种类反推。对比之下 `explore` 已经会按签名造边界输入 ——
   那条能力挪一半给 `verify`（对每处存活变异，在取值池里找一个能翻面的输入并报出来），
   人工成本就会从"猜"变成"挑"。登记为 P14。

## 5. 怎么重跑

```sh
cd <仓库根>
go build -o .build/droplet ./code/lang/cmd/droplet
for t in size_ok retryable can_write; do
  for f in a b c; do .build/droplet verify docs/validation/p6/$t/$f.dlt; done
  .build/droplet explore docs/validation/p6/$t/{a,b,c}.dlt
  .build/droplet verify docs/validation/p6/$t/intent.dlt   # 占位实现应被样例否掉
done
```

退出码：`verify` 有样例不成立或有变异存活 → 1；`explore` 存活多于一个 → 1。
`explore` 的输出会把"每条样例在每个候选上的 PASS/FAIL"并排列出，这就是分歧点名。

## 6. 这一份算不算 P6 的完成

**不算。** P6 要的是"方法在真实任务上成不成立"，而 §1 的偏置使它只能证明
**流程和工具有效、且方法有一个未处理的前提（等价候选）**。
按判据原样收口，结论应该是 NEXT 里那条预写判据的第三种结局 ——
"多数题在 3 轮内不收敛"，但**原因不是意图表达力不足**，
而是**工具的收敛判定比判据 A 严，且严在不可能满足的地方**。所以下一步分两半：

- **P15**：把 `explore` 的收敛判定改回判据 A 的口径（三分：唯一存活 / 有分歧 = 欠定 /
  无分歧 = 未证分歧并注明所用输入集）。这是 §7.8.3-1 的**实现偏差**，不是判据要改。
- **P14**：让 `verify` 对每处存活变异报出一个能翻面的输入（复用 `explore` 的取值池）。
- **P6 复跑**：候选换成作者从不可控模型取得的三份，其余流程与本题面不变，
  这样"首次通过率 / 收敛轮数 / 人补样例条数 / 人分钟数"才有意义。

本轮不动 `code/lang`：H8 仍 7993 / 8000（余量 7 行），用例 142。
