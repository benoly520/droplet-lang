# Droplet（中文版）

一门**面向「AI 生成、人类维护」的服务端编程语言**。

更准确的定位：**"生成—验证"范式的使能层** —— 程序不再是被写出来的，而是从众多候选中被**证明并挑选**出来的；人的职责从写实现，变成写意图与反例。

Droplet 只优化一件事：**让 AI 的错误无法保持沉默，让验证便宜到代理真的会去跑。** 不是"造一门更安全、更抽象、更优雅的语言"，而是造一门错误藏不住、检查以毫秒计、运行时轻到能塞进最小生产实例的语言。

> **状态：D0 已实现，D1 未开始。** 一个 91 行的示例服务（契约 + 入口）能编成 C11 二进制，以不到 2 MB 常驻内存启动并讲 HTTP/1.1；58 个 Go 测试覆盖 lexer、parser、checker、生成器、host 能力签名、运行时死代码审计、AST 转储与契约导出。已实现的语言是设计的**有偏子集**，每一处缺口都带原因与补齐里程碑，见 [docs/D0-DEVIATIONS.md](docs/D0-DEVIATIONS.md)。完整提案见 [docs/SPEC.md](docs/SPEC.md)（§0 范式定位、§5.9 设计模式与 OOP 取舍、§5.10 意图一等公民、§7.8 收敛判据、§9 生产资源预算、附录 C 设计包袱自审）。英文版见 [README.md](README.md)。

## 快速开始

```sh
mkdir -p .build
(cd code/lang && go build -o ../../.build/droplet ./cmd/droplet)

# 最小闭环：源码 → C → 二进制 → 标准输出
.build/droplet build code/lang/examples/hello.dlt -o .build/hello && .build/hello   # world

# 示例服务：契约 + 入口 → 二进制 → HTTP
.build/droplet contract code/webapi/src/contract.dlt code/webapi/src/main.dlt      # JSON 契约 + 变体编号
.build/droplet build    code/webapi/src/contract.dlt code/webapi/src/main.dlt -o .build/blobd
mkdir -p .build/data    # DP_ROOT 必须先存在，否则服务启动即退出
DP_ROOT=.build/data DP_TOKEN=t .build/blobd &
curl -s -X PUT -H 'Authorization: Bearer t' --data 'hello' localhost:8787/v1/blob/demo
curl -s        -H 'Authorization: Bearer t' localhost:8787/v1/blob/demo              # hello
```

`sh code/webapi/deploy/accept.sh` 跑 12 项边界验收（412 / 405 / 413 / 501 / ETag …）；`sh code/webapi/deploy/soak.sh` 是长时间泄漏观测。

## 核心想法

LLM 写服务端代码之所以出错，多数不是因为"写不出来"，而是因为**正确性藏在模型看不见的地方**：看起来无害、其实动了数据库的函数；契约写在字符串标签里的结构体；可以被丢掉的错误；活得比一次请求更久的状态；只在部署时才炸的配置。

Droplet 的对策是把这些事实变成**签名上可见、编译期可检查**的东西 —— 让代理能自己发现并修好错误，而不是依赖人来兜。

## 硬约束

| # | 约束 | 目标值 |
| --- | --- | --- |
| H1 | 教学面（规范 + 全部规则 + 核心 API 清单，机器可读形式） | ≤ 2000 token —— **这是"不需要重新训练模型"的前提** |
| H2 | 核心关键字数量 | ≤ 14 |
| H3 | 核心原语数量 | ≤ 24 |
| H4 | 生产环境空服务常驻内存（RSS） | ≤ 3 MB |
| H5 | 空闲 CPU / 每请求固定开销 | ≤ 单核 0.5% / ≤ 2 µs |
| H6 | **边际内存**：每新增一条路由 / 一个并发任务的增量 | 由 `droplet mem` 报告并纳入 CI 预算 |

H1 与 H4–H6 从两个方向夹住这门语言：一个限制**你要教模型多少东西**，另两个限制**你要在运行时里藏多少东西、每加一个功能又藏多少**。空服务 3 MB、加 20 条路由变 80 MB 不算达标 —— 真实账单是 `路由数 × 每路由增量 × 实例数`。几条纪律指向同一个方向 ——

> **省资源和防错是同一个动作。** 隐形机制之所以隐形，是因为它在运行时替你做了一个源码里看不见的决定；而它每做一次决定，就在内存里占一块地方。**AI 验证不了的东西，通常也正是最贵的东西。**

（H4/H5 目前是**目标值而非实测值**，需在 S1 阶段复核；达不到就回去删运行时机制，不允许放宽阈值。）

## 范式（SPEC §0）

过去所有范式都在优化同一种稀缺资源：**人的理解带宽**。抽象、封装、设计模式、类型系统，全是"省人脑"的设计。现在成本结构反转了：**候选代码几乎免费，验证成为瓶颈。** Droplet 的作用是让新循环在经济上跑得起来：

```
意图（性质 + 契约 + 边界 + 样例）
   → 候选集（AI 生成，多个，随机）        ← 随机性只允许存在于这一步
   → 验证器（类型 / 效果 / 资源 / 性质 / 重放 / 变异检验）
   → 存活者 → 确定性的、人可读可 diff 的源码（交付物）
```

三条不可妥协：**运行时必须确定**（概率语义会摧毁"可替换性"，那是过去五十年编程能力的地基）；**交付物必须人可读**；**验证必须亚秒级**。正在考察的新组合律是"性质并集 + 效果子集 + 资源预算可加"—— **原创性落点在组合语义，不在语法。**

一句话版本：**旧范式为省人脑而设计；新范式为可验证性而设计；而新范式跑不起来，除非有一门语言把"意图"做成一等公民、把"验证"做到毫秒级、把"运行时"压进最小实例。Droplet 就是那个"除非"。**

**收敛判据（已定，SPEC §7.8.3）：存活候选之间存在外部可观测的行为差异时，构建直接失败（`E12`），由人补一条约束。** 语言刻意**不提供任何"自动挑一个"的路径** —— 没有 `strategy: minimal`、没有默认候选、没有 last-known-good 回退。因为一旦允许自动收敛，"必填意图"就退化成"可选文档"，整个使能层随之归零。探索期"先看看有哪些候选"的需求由 `droplet explore` 承担，其产物明确不可发布。这个选择的代价也如实记账：意图欠定变成了**人**的新瓶颈 —— 该项成本用指标衡量（`E12` 触发频次与平均补约束耗时，§11.3），而不是靠辩护过去，并且它构成主张 P-D 的一条独立证伪路径。

**诚实声明（SPEC 附录 C）**：草案对自己做过一次"历史包袱审计"，承认有三处从未被质疑的结构性假设 —— *程序=文本*、*思考单位=函数*、*部署不属于语言职责*。其中两项被列为必须先做的实验（V1 状态机为一等单位、V2 AST 身份与语义 diff），**在它们出结果之前不允许冻结语言核心**。

## 设计支柱

- **没有逃生口** —— 不存在 `any` / `as` / `unsafe` / `#[allow]` 的等价物。一个以"让构建通过"为目标的代理，会系统性地滥用任何存在的出口。
- **效果写进签名** —— 一个函数能碰什么（哪个库、哪个外部主机、时钟）是类型层事实；没有环境权限，没有全局 `fetch`，没有隐式读环境。
- **仿射类型 + 显式区域** —— 资源泄漏、事务跨越网络调用都变成编译错误；同一套模型给出裸机所需的静态内存上界。
- **边界是声明出来的，不是猜出来的** —— RPC / 队列 / HTTP 的载荷、版本、幂等性要求集中在一个 `boundary` 构造里，一次声明同时产出调用桩、服务端入口、序列化代码与机器可读契约。
- **类型化配置 + 不透明密钥** —— 某个环境少一个键，是构建失败，不是凌晨告警；密钥在类型上不可打印、不可写日志。
- **资源预算是类型** —— 每请求内存上限、缓存容量都是可检查的事实，于是"无界查询"和"无界缓存"这两类最贵的服务端事故在编译期就被消灭。
- **错误是不可丢弃的值** —— 只能三选一：向上传播、处理干净、或写下带理由的显式 `ignore(reason)` 并留痕。
- **意图是输入面，不是注释** —— `requires` / `effects` / `cap` / `idempotent` / `invariant` / `example` 会参与检查、参与变异检验、参与收敛（SPEC §5.10）。对外入口或边界方法若没有可检查意图，**不允许编译**（`E11`）；写了但对变异零捕获的意图同样是硬错误（`E10`）。
- **单一静态二进制**，无解释器、无虚拟机、无 JIT、无守护进程。
- **模式塌缩，OOP 一分为二** —— 保留词汇（`Repository` / `Gateway` / `handler` 是免费的检索先验），删除机制（继承、虚分派、注册表、装饰器链）。访问者、策略、建造者、工厂、单例、Unit of Work 各自消失成一个原语，而不是一套惯例（SPEC §5.9）。

## 路线图

| 阶段 | 交付物 | 通过判据 |
| --- | --- | --- |
| S0 | 规范冻结 | 五条硬约束在纸面上成立 |
| S1 | **不写编译器的语义验证**（宿主语言实现检查器原型 + 消融实验） | 首次通过率显著优于基线；误报率 < 5% |
| S2 | 自举：真语法 + C 后端 + `droplet check` / `mem` / `bench` | 真实服务跑通；空服务 RSS ≤ 3 MB 实测达标 |
| S3 | 服务端最小可用栈 | 有非作者用户跑在生产环境 |
| S4 | 裸机后端 | "同一门语言从 MCU 写到服务器"成立 |

**S1 是回报线**：它在任何人写下编译器之前，检验那个核心主张 —— **一门足够小的语言，能否让 AI 在不被重新训练的前提下一次写对。** 若数据不达标，沉没成本只有一份规范和一个检查器。
