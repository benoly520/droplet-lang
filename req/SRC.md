# 源需求（原文，逐句编号）

> 这份文件是“用户说的”，只编号、不改写、不润色。翻译产物在 `REQ.tsv` / `TRANS.tsv`。
> 任何一句被删改，冻结清单都会红；加一句就是加一条需求，必须重新走翻译与冻结。

S1 探活接口不需要鉴权，始终返回 200。
S2 同一个 key 的读取必须返回最近一次成功写入的字节；覆盖写之前保留上一版本快照。
S3 清单必须来自数据目录本身，不依赖任何额外的注册表文件。
S4 创建 key 只在 key 不存在时成功，成功时 201 且没有 body；重复创建返回 409。
S5 每一次成功写入恰好留下一条版本化提交。
S6 所有错误响应都不携带 body。
S7 读取不存在的 key 返回 404；key 不合法返回 400，不进入业务处理。
S8 ETag 由 body 推导，同一份表示只有一个版本号；未声明的动词一律 405。
S9 204 响应不得带 Content-Length，也不得带 body。
S10 带 If-Match 写入时，相符才放行，不符返回 412 且没有 body。
S11 配置了 token 时，缺 token 或 token 不符一律 401；/health 与未配置 token 的情况例外。
S12 超过 APP_MAX_BODY 的请求一律 413。
S13 启动端口只接受 1 到 65535，0 和 65536 不得启动。
S14 清单响应必须是一个 JSON 对象，顶层键为 keys，值是按字典序排列的字符串数组。
